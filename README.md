### 1. 앱 소개

**MOCA — 내 차를 키우는 차량 관리 파트너.**

MOCA는 차량이 알려 주는 부품 상태를 읽어 **0~100점과 등급(S+~D)** 으로 보여 준다. 앱을 켜면 점검이 먼저 돈다. 점수가 낮은 구역부터 감점 원인과 해결 방법(정비소 방문 · 용품 구매 · 직접 해결)을 보여 주고, 차량 내비 안내와 휴대폰 QR 로 이어 준다. 말로 물으면 내 차 데이터를 근거로 답한다. 연습 상대와 점수를 겨루고, 진 구역은 무엇을 고치면 되는지 알려 준다.

### 2. 주요 기능

하단 탭은 **홈 · 상태관리 · 보이스챗 · 대전하기 · 설정** 이다. 「점검하기」 화면은 없다. 점검은 앱을 켤 때(앱 시작 화면)와 상태관리의 [다시 점검]에서 한다.

**처음 켤 때** 동의 3개(① 차량 상태로 점수 계산 ② 음성 질문과 점수 요약을 서버를 거쳐 AI에 전송 ③ 대전 상대에게 닉네임·등급·점수 표시)에 **모두** 동의해야 한다. 하나라도 거절하면 「동의하지 않으면 서비스를 이용할 수 없어요」를 보여 주고 앱이 종료된다. 건너뛰기는 없다. 닉네임은 한글·영문·숫자 2~10자이고, 비우면 「드라이버」+숫자 4자리가 된다.

**앱 시작 화면.** 자동 점검 뒤 등급·종합 점수, 켜진 경고등, 구역 5개 점수, 조치 항목(최대 3개), 연료·배터리 잔량, 측정 불가 수를 보여 준다. 1분 뒤 메인으로 넘어간다(정차 중 빨간 경고등이 켜져 있으면 머문다). 주행 중에는 등급·경고등만 보이고 바로 메인으로 넘어가며, 빨간 경고등이면 음성으로 정차를 안내한다.

**메인.** 등급·종합 점수, 경고 배지(「주의 n」/「주의 없음」), 「○분 전 점검 기준」, 기능 단추 3개.

| 기능 | 내용 |
|---|---|
| 상태관리 | 2D 자동차 그림(구역 5개·바퀴 4개를 상태 색으로. 지금 그림은 자리표시). 점수 낮은 구역부터 카드. 감점 원인별 해결방안(정비소 방문 / 용품 구매 / 직접 해결). [정비소 찾기] · [주유소 안내] · [충전소 안내]. 용품 QR 이미지 2개(워셔액, 휴대용 타이어 공기 주입기). [다시 점검], [AI에게 물어보기], 점수 추이 그래프. 데모 D3 에서는 [ABS 해결 (데모)] |
| 보이스챗 | 「지금 내 차」 요약 카드와 근거 한 줄. 다른 화면에서 넘어온 항목 카드와 추천 질문 3개. 내비를 조작하기 전 확인 카드([안내 시작]/[취소]). 먼저 제안(빨간 경고등 → 정비 항목 → 연료·배터리 10% 미만). 경유지(최대 2곳)와 안내 취소. 주행 중에는 키보드 입력을 막고 답을 2문장 이내로 한다. 서버가 안 되면 기기 안의 답(길 안내 포함)으로 넘어간다 |
| 대전하기 | 구역 5개를 한 라운드씩 겨룬다. [대전 시작]을 누르면 두 차가 마주 달려와 부딪치는 3D 영상(6초)이 나오고, 진 쪽 차는 부서지고 이긴 쪽은 멀쩡하다(영상은 미리 렌더링해 넣었다, `tools/crash3d`). [건너뛰기]. 결과 뒤 「이 차만큼 관리하려면」(진 구역별로 해결할 감점 원인과 [해결하러 가기])과 앞선 구역 정리, 전적. 상대는 **연습 상대만**이다(데모는 시나리오별 고정 상대). **월간랭킹**: 연습 상대 12명과 나, 「데모 데이터」 배지, 이번 달 관리 요약(점검한 날, 연속 점검, 해결한 항목, 1위와의 차이, 따라잡는 방법), [질문하기] → 보이스챗 |
| 설정 | 닉네임 보기·바꾸기, 데모 모드와 시나리오 D0~D7, [내 데이터 삭제], 오픈소스 라이선스, 앱 정보. 동의를 켜고 끄는 스위치는 없다. 동의 철회는 데이터 삭제로 한다 |

**내비 연동.** Pleos NaviHelper SDK 3.0.5 에는 「근처 장소 목록」을 돌려주는 함수가 없다(확인됨). 그래서 둘로 나뉜다.

| 모드 | 동작 |
|---|---|
| 실제 모드 | 내비의 **검색 화면**을 연다(충전소는 내비의 「가까운 충전소」 화면). 목적지는 내비에서 고른다 |
| 데모 모드 | 앱에 넣은 **장소 목록의 좌표**로 안내·경유지·취소를 한다. 「데모 데이터」 배지가 붙는다 |

에뮬레이터에서 좌표 안내를 요청한 뒤 내비가 안내 시작 알림을 보내는 것까지 확인했다.

**점수의 출처.** 받는 항목과 상태 종류는 차량 API 를 따른다. 경고등 색의 순서(빨강 > 노랑)만 ISO 2575 를 따른다. **감점 숫자(−50, −40, −25, −20, −10 등)와 잔량 10% 기준은 팀이 정한 설계 판단**이고, 정비 규격에서 나온 값이 아니다. 자세한 구분은 별지 2쪽.

**데모 모드.** 시나리오 D0~D7. 데모 데이터를 쓰는 화면에는 「데모 데이터」가 보인다.

### 4. 실행 방법

**앱 (에뮬레이터)**

```bash
# 1) Pleos 에뮬레이터 (창 없는 모드 — 이 맥에서 창 모드는 QEMU가 멈춘다)
export ANDROID_HOME="$HOME/Library/Android/sdk"
"$ANDROID_HOME/emulator/emulator" -avd Pleos_Connect_v2.1.0 \
  -no-snapshot-load -gpu host -no-audio -no-window &

# 2) 앱 빌드·설치
cd app
echo "sdk.dir=$HOME/Library/Android/sdk" > local.properties
./gradlew :app:assembleDebug
"$ANDROID_HOME/platform-tools/adb" install -r app/build/outputs/apk/debug/app-debug.apk
"$ANDROID_HOME/platform-tools/adb" shell am start -n ai.moca.app/.MainActivity
```

- `app/settings.gradle.kts` 는 `pleos-ds` 모듈을 `../../pleos-connect-design-system/pleos-ds` 에서 가져온다. 이 저장소와 같은 위치(저장소 폴더의 옆)에 `pleos-connect-design-system` 폴더가 있어야 빌드된다. 이 폴더는 이 저장소에 들어 있지 않다. 빌드 없이 확인하려면 `apk/` 의 APK 를 설치한다(다시 빌드한 뒤).
- 에뮬레이터에 release 서명 앱이 이미 깔려 있으면 debug APK 설치가 거부된다. 그때는 `adb uninstall ai.moca.app` 로 지우고 다시 설치한다.
- 에뮬레이터의 실제 모드는 등급이 나오지 않는다(정직 고지 참고). **화면 확인은 설정에서 데모 모드를 켜고 시나리오(D0~D7)를 고른다.** D3 이 대표 이야기다.

**서버 (로컬, AI 답변용)**

```bash
cd server
node local.mjs            # 127.0.0.1:8787, SQLite는 moca.sqlite
```

`HIVE_API_KEY` 는 환경변수로만 넣는다. 키가 없으면 `/chat` 은 502를 돌려주고, 앱은 **오프라인 음성**(기기 안의 답)으로 넘어간다.

```bash
HIVE_API_KEY=... node local.mjs
```

debug 빌드의 서버 주소는 `http://127.0.0.1:8787` 로 들어 있다(`app/app/build.gradle.kts`). 에뮬레이터 안에서 이 주소가 맥의 서버에 닿게 하는 방법은 이 README 에서 돌려 보지 않았다(확인 필요). release 빌드의 서버 주소는 빌드할 때 넣고(`-Pmoca.serverBaseUrl=`), 비어 있으면 앱은 서버를 부르지 않고 기기 안의 답으로 동작한다. 서버 코드에는 예전 경로(`/snapshots` `/events` `/rank` `/opponent`)가 남아 있지만 앱은 부르지 않는다. 앱이 쓰는 것은 `POST /chat` 과, 데이터 삭제 때의 `DELETE /snapshots` 뿐이다.

**테스트**

```bash
./check.sh          # 서버 테스트 + :core 테스트 + 빌드 + 앱 테스트 + lint + 정적 검사
./check.sh --quick  # 서버·:core 만
cd server && node --test
cd core && ./run-tests.sh      # JDK 17. kotlinc 가 없으면 ~/.gradle 의 Gradle 에 든 컴파일러를 쓰므로 Gradle 빌드를 한 번 해 둔다
cd app && ./gradlew :app:testDebugUnitTest
python3 -m unittest tools/test_moca_eval.py
```

## 테스트 환경 및 필요한 설정

- macOS, JDK 17
- Android SDK: platform-tools, emulator, build-tools 36.0.0 (`ANDROID_HOME=$HOME/Library/Android/sdk`)

- Python 3 (평가 도구 단위 테스트, 정적 검사)
- 서버 주소 설정: `.env.example` 참고 (`.env` 에 실제 값, 커밋하지 않음). 자세한 실행 방법은 위 「4. 실행 방법」.

Pleos Connect 에뮬레이터 v2.1.0 (AVD `Pleos_Connect_v2.1.0`, Android API 34). 화면 규격 2560×1440, density 160. 앱은 이 화면의 오른쪽 패널에 뜬다.

에뮬레이터는 `-gpu host` 로 띄운다. `-gpu swiftshader_indirect` 로 띄우면 에뮬레이터의 주행 화면 앱이 되풀이해 죽어 터치가 앱에 전달되지 않는다(2026-11-11 실측).

`:core` 를 분리한 이유: 점수 엔진을 Android SDK 없이 JDK 17만으로 테스트하기 위해서다.

## 점수 규칙 (요약)

- 구역 5개: 동력, 제동·조향, 타이어, 전기, 안전. 구역 점수는 100에서 원인 묶음별 감점을 뺀다. 같은 묶음은 가장 큰 감점 하나만. 읽지 못한 값은 「측정 불가」이고 계산에서 뺀다.
- 건강 = 측정된 구역 점수의 평균. 종합 = 건강×0.7 + 관리×0.3.
- 등급: S+ ≥95 · S ≥90 · A ≥80 · B ≥70 · C ≥60 · D <60.
- 측정된 구역이 3개 미만이면 등급을 내지 않는다.
- 감점 대상 빨간 경고등이 켜져 있으면 등급 상한 B. **건강 문턱**: S는 건강 ≥90, S+는 건강 ≥95 일 때만. 건강이 90 미만이면 A 상한.
- 관리: 매달 1일 50에서 시작. 점검한 날 +2, 7일 연속 +5, 해소 +5(하루 최대 +10), 14일 미점검 이후 하루 −1. 앱을 켤 때마다 점검하므로 「점검한 날」은 사실상 「앱을 켠 날」이다.
- 표시: 종합은 소수점 버림.
- 대전 결과는 전적에만 쌓이고 점수·등급에는 반영하지 않는다.
- 감점 숫자는 설계 판단이고, 경고등 색의 순서만 ISO 2575 를 따른다(위 「점수의 출처」).

## 알려진 제약

- **에뮬레이터의 실제 모드는 등급이 나오지 않는다.** 엔진오일·브레이크액·변속기오일·워셔액·연료와 타이어 현재 공기압 속성이 없다. 데모 모드(D0~D7)로 화면을 확인한다.
- **실차에서는 확인하지 못했다.** 경고등 종류·색 숫자, 경고등 읽기 권한, 누적 주행거리 단위(0.5절 확인 필요 목록).
- **실제 모드의 내비는 검색 화면까지만 연다.** 근처 장소 목록을 돌려주는 SDK 함수가 없다. 좌표로 안내하는 것은 데모 모드(장소 목록)뿐이다.
- **2D 자동차 그림은 자리표시**이고, **QR 은 상품명을 지정한 쿠팡 검색 주소**다(상품 번호는 자주 바뀌어 쓰지 않음, 제휴 연동 예정).
- **상대는 연습 상대뿐**이다. 실제 사용자와의 대전·순위는 2차 PT 범위 밖이다.
- **주행 중 제한은 코드만 있고 실행해 보지 못했다.** 이 에뮬레이터에서는 주행 상태를 만들 수 없다.
- **음성은 글자 입력으로 확인했다.** 에뮬레이터에 마이크가 없다.
- **서버 답은 5~11초 걸린다**(2026-11-12 에뮬레이터 6회, 이전 버전 앱). 서버가 답하지 못하면 기기 안의 답으로 넘어간다.
- **서버의 횟수 제한(429)은 테스트로만 확인했다.**
