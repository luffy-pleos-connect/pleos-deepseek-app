# REVIEW — MOCA 숏폼 30 s

작성 시각 기준: 렌더 `out/MOCA_shorts_30s.mp4`(1080 x 1920, 30 fps, 30.000 s, H.264 High yuv420p ~11 Mbps, AAC 48 kHz). 검토는 만든 쪽이 직접 했다(별도 검토자 없음) — 다음 턴에서 새 눈으로 한 번 더 보길 권한다.

## 총괄 검토 반영(2차 렌더)
- 흰 사각형: 원인은 «데모» 가림 상자가 아니라 **카드가 자기 장면 시작(와이프가 덮기 전) 부터 그려져 아래에서 올라오며 비쳤던 것**(상태관리 2 -> 보이스챗 이음 9.6~10.4 s, 대전 결과 -> 해결 이음 22.9~23.4 s). 카드 불투명도 0 으로 시작해 착지 시점에 켜도록 고침. 가림 상자는 모두 없앰(`c2`·`c5`·`c7` 재인코딩, 글자는 자르는 범위로 해결).
- 파란 점: 해결 장면의 파랑 원형 번짐이 아래 가운데(y 1766)에서 반지름 0 으로 시작해 첫 프레임에 점으로 보였음 -> 번짐을 0.1 s 늦게 시작하고 `power3.out` 으로 바꿈(점 단계 없음). 브랜드 장면의 번짐도 같이.
- 가독성: 카드를 940 x 652 로 키우고(해결 장면 940 x 540) 장면 첫 프레임부터 핵심 UI 확대. 원본 대비 출력 배율 0.94~1.3, 앱 창 전체를 작게 보이는 컷 0 개. 대전 결과·보이스챗 답 문장은 원본에서 한 줄이 1,000 px 보다 길어 한 화면에 안 들어간다 — 결과는 «부서진 파란 차 + 2:2·종합 75 대 88» 구간만, 답 문장은 카메라가 문장을 따라 오른쪽으로 이동(약 12.3~12.9 s).
- 문법: 상태관리 2 와 길 안내 두 컷은 베젤 없는 full-bleed.
- 해결 장면 카드: 515 -> 568 px 높이, 폭 672 -> 968 px.
- 0.5 s 간격 60 장 전부를 직접 확인(아래 파일). 흰 사각형·빈 화면·잔여 점·안전 영역 침범 없음.

## 내가 정한 것
- 이야기: 후보 3개(`STORYLINES.md`) 중 A «한 대의 차, 한 개의 숫자(B · 75 -> A · 83)». 사용자 제안 흐름(충돌 훅 -> 브랜드 -> 상태관리 -> 보이스챗 -> 대전 -> 해결 -> 끝)을 그대로 따르되 두 가지를 바꿨다: (1) 보이스챗 뒤에 실제 내비 경로(경로 3개 + 진행 화면)를 별도 4.4 초 줄로 넣음, (2) 대전은 3D 충돌 뒤에 결과 화면(75 대 88)을 1.3 초 붙여 «졌다 -> 고친다» 로 해결 장면과 이어지게 함.
- 훅: 3D 슬로모션(`crash_v_slowmo.mp4`, 0.5x)으로 첫 프레임부터 정면 충돌 직전, 접촉 1.0 s, 곡 드롭 1.765 s 에 두 번째 충격. 3D 충돌 두 장면은 다른 작업자가 만든 영상(`crash_v_slowmo.mp4`, `crash_v_red_wins.mp4`)이다. 약속된 이름 `crash_v_slowmo_closeup.mp4` 는 도착하지 않아 `crash_v_slowmo.mp4` 로 대체했다(내용은 가까운 측면 슬로모션).
- 대전 3D 는 `red_wins`(파란 차 = 내 차 «드라이버5173» 이 부서짐)를 골라 앱 결과(75 대 88 로 짐)와 맞췄다. `blue_wins` 는 쓰지 않았다.
- 코드로 그린 것: 차량 디스플레이 베젤, 커서(앱 녹화에 커서가 없어서 클릭 순간을 알려 주려고 추가), 장면 사이 이음 효과, 거대한 배경 숫자. 앱 화면 글자·값은 한 글자도 새로 쓰지 않았다.
- 로고: 앱 런처 아이콘 벡터 path 를 그대로 사용, 워드마크는 Pretendard Black 조판.

## 눈으로만 본 것 / 아무도 안 본 것
- 소리는 들어 보지 못했다(측정만). 효과음 타이밍은 `audio` 가 알려 준 피크 시각으로 계산했고 렌더 파형에서 충격 두 곳이 보이는 것까지만 확인했다.
- 실제 폰·유튜브 쇼츠 UI 위에서의 겹침(우측 버튼 줄·하단 캡션)은 확인 못 했다. 규격 수치만 지켰다.
- 앱 화면 글자는 출력 1080 px 기준 대부분 26~40 px(원본 글자 x 배율 0.94~1.3) 이다. 폰 폭(360 px)에서의 실제 읽힘은 확인 못 했다. 모든 앱 장면에 자막을 따로 두었다.

## 고친 것(검토에서 나온 순서)
0. (2차) 위 «총괄 검토 반영» 참고.
1. P0 글자 간격: «고치면 등급이» 가 붙어 보임 -> 줄 안 span 사이 0.26em 간격(`.cap .ln span+span`).
2. P0 커서가 엉뚱한 버튼을 가리킴 -> 녹화 화면의 실제 버튼 좌표(앱 1225,725 / 825,945)로 수정.
3. P0 우측 가장자리에 whip 중인 카드 조각이 보임 -> 시작 x 를 +1000 에서 +1120 으로.
4. P1 대전 결과 화면 확대가 양쪽 열을 잘라 먹음 -> 1.35x 에서 1.12x.
5. P1 대전 3D 의 접촉 시각이 20.19 s 와 어긋남 -> 영상 0.05 s 부터 시작해 접촉 = 20.19 s, 큰 불꽃 ~21.0 s 와 «진 쪽은 박살»(20.84 s) 맞춤.
6. P1 아래 1/3 이 빈 단색 -> 장면 숫자 거대 배경(상태 75, 보이스챗 75, 대전 75:88, 해결 83), 브랜드·끝에는 로고 심볼.
7. P1 훅 첫 프레임에 차가 가장자리에 걸쳐 있음 -> 재생 0.5x, 시작 0.5 s 로 바꿔 첫 프레임부터 정면 충돌 직전.
8. P2 끝 카드 첫 0.1~0.4 s 가 비어 있음 -> 아이콘 선 그리기를 0.17 s 당김.
9. 음량 -13.2 LUFS -> 곡 0.5 -> 0.46 로 -13.7 LUFS.

## 가장 약한 컷, 시간이 더 있다면
- 해결 장면(23.43~26.03 s)은 카드를 940 x 540 으로 키웠지만 차 그림 아래쪽(안전 구역)이 카드 아래에서 잘린다. 숫자를 더 줄이면 해결.
- 앱 장면은 «카드(베젤)» 와 «full-bleed» 두 가지 틀이다. 시간이 있으면 카드가 컨테이너째 full-bleed 로 늘어나는 변형(예: 확인 카드 -> 내비 창)을 만들고 싶다.
- 대전 결과는 부서진 파란 차 쪽만 확대해서 오른쪽(이긴 빨간 차)이 잘린다.
- 보이스챗 «생각 중» 구간(녹화에서 3.3 s)을 점프컷으로 줄였다(12.04 s dip). 시청자에게는 «답이 바로 나온다» 로 보인다 — 실제 대기 시간이 짧다는 주장은 아니다. 홍보 문구(«바로 답해요»)는 이 편집에 기대고 있으니 팀이 괜찮은지 확인해 달라.
- «내 차 점수» 칩이 화면에 0.9 s(3.92~4.85 s + 이음). 규칙 1.05 s 아래지만 4 음절 큰 글자이고 곡 박자(beat 2)에 맞춘 것이라 두었다.

## 남긴 경고와 이유
- `line_unread` «내 차 점수» 0.90 s — 위 이유.
- `nested_media_start_basis_ambiguous` x 12 — 하위 장면 안 `<video>` 의 `data-start` 가 0 이 아닌 것에 대한 안내성 경고. 모두 장면 기준 시간으로 의도한 값.
- 3D 충돌 영상 자체에 불꽃·반사 광(글로우)이 있다. 우리가 얹은 장식 글로우는 없다.
