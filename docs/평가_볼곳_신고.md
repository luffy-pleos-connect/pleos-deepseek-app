# 평가 조작·볼 곳 신고

이 문서는 「MOCA 기능별 평가기준표」 2장에 따라, 평가자가 앱을 조작하고 값을 읽을 때 쓸 노드의 `resource-id` 를 신고한다. 적은 id 는 모두 저장소의 레이아웃 XML 과 Kotlin 소스에 실제로 있다.

- 패키지: `ai.moca.app`
- 화면 전환은 `MainActivity` 가 Fragment 를 교체하는 방식이다(`app/app/src/main/java/ai/moca/app/MainActivity.kt:134` `show()`).
- 아래 표의 id 는 `@+id/이름` 으로 레이아웃에 있거나, 코드에서 만드는 뷰는 소스 파일:줄을 함께 적었다. 코드로 만든 뷰는 `uiautomator` 에서 resource-id 가 없다.

## 조작 신고

| 번호 | 조작 | 누르는 노드 (resource-id) |
|---|---|---|
| 조작-1 | 데모 켜기: 홈 탭 `ai.moca.app:id/tabSettings` 누름 → 설정 화면에서 스위치 `ai.moca.app:id/switchDemo` 를 눌러 ON. 데모 끄기: 같은 스위치를 다시 눌러 OFF. 켜고 끌 때마다 액티비티가 다시 만들어진다(`SettingsFragment.kt:33`) | `ai.moca.app:id/tabSettings` → `ai.moca.app:id/switchDemo` |
| 조작-2 | 데모 시나리오 D0~D6 고르기: 이 앱 빌드에는 설정 화면에 시나리오 고르는 UI 가 없다. 시나리오는 `ai.moca.app:id/switchDemo` 를 끈 상태에서 바꿀 방법이 없고, 저장된 값(`demo_scenario`, 기본값 D3)은 `SettingsFragment` 가 읽기만 한다. 바꾸는 유일한 방법은 디버그 자동 시연이 아니라 `adb shell` 로 SharedPreferences 파일을 바꾸는 것이다: 앱을 강제로 끈 뒤(`adb shell am force-stop ai.moca.app`) `adb shell` 로 `/data/data/ai.moca.app/shared_prefs/moca_prefs.xml` 의 `demo_scenario` 값을 `D0`~`D6` 가운데 하나로 바꾸고 앱을 다시 켠다. 값이 없으면 D3 이 쓰인다(`Prefs.kt:79`) | 파일 수정이므로 누르는 노드 없음 |
| 조작-3 | 화면 이동: 하단 탭 바의 단추를 누른다. 홈→점검하기: `ai.moca.app:id/tabHome` 화면에서 타일 `ai.moca.app:id/tileInspect`. 홈→상태관리: `ai.moca.app:id/tileStatus`. 홈→AI 보이스: `ai.moca.app:id/tileVoice`. 홈→대전하기: `ai.moca.app:id/tileBattle`. 홈→설정: `ai.moca.app:id/tabSettings`. 어느 화면에서든 홈으로 돌아오기: `ai.moca.app:id/tabHome` | `ai.moca.app:id/tabHome`, `ai.moca.app:id/tabStatus`, `ai.moca.app:id/tabVoice`, `ai.moca.app:id/tabBattle`, `ai.moca.app:id/tabSettings`, `ai.moca.app:id/tileInspect`, `ai.moca.app:id/tileStatus`, `ai.moca.app:id/tileVoice`, `ai.moca.app:id/tileBattle` |
| 조작-4 | 점검 시작: 홈 타일 `ai.moca.app:id/tileInspect` 를 누르면 InspectFragment 가 열리면서 즉시 점검이 시작된다(`InspectFragment.kt:30`). 다시 점검: 점검 화면의 단추 `ai.moca.app:id/buttonInspectAgain` | `ai.moca.app:id/tileInspect`, `ai.moca.app:id/buttonInspectAgain` |
| 조작-5 | 상태관리 카테고리 카드의 상세 열기: 카드 전체(`ai.moca.app:id/categoryContainer` 안의 카드, id 없음 — 볼 곳 신고 「상태.카드」 참고)를 누른다. 카드를 누를 때마다 상세 텍스트가 펼쳐졌다 접힌다(`StatusFragment.kt:121-123`) | `ai.moca.app:id/categoryContainer` 안의 카드 LinearLayout — id 없음, 카테고리 이름 글자가 든 노드를 누른다 |
| 조작-6 | 글로 질문 보내기: 입력 칸 `ai.moca.app:id/questionInput` 에 글자를 넣고 단추 `ai.moca.app:id/sendButton` 을 누른다(`VoiceFragment.kt:68-74`). 음성 입력 시작: 단추 `ai.moca.app:id/micButton` 을 누른다(`VoiceFragment.kt:122`). 화면의 추천 질문 단추 `ai.moca.app:id/suggestion1`~`ai.moca.app:id/suggestion4` 를 눌러도 질문이 바로 보내진다(`VoiceFragment.kt:75-77`) | `ai.moca.app:id/questionInput` + `ai.moca.app:id/sendButton`, `ai.moca.app:id/micButton`, `ai.moca.app:id/suggestion1`, `ai.moca.app:id/suggestion2`, `ai.moca.app:id/suggestion3`, `ai.moca.app:id/suggestion4` |
| 조작-7 | 대전 시작: 대전 화면의 단추 `ai.moca.app:id/buttonStartBattle` 을 누른다(`BattleFragment.kt:63`). 라운드 진행을 기다리지 않으려면 `ai.moca.app:id/buttonSkip` 을 누른다 | `ai.moca.app:id/buttonStartBattle` |
| 조작-8 | 서버 주소와 켜는 명령: 서버 주소는 빌드 타입별로 고정돼 있다. debug 빌드는 `http://127.0.0.1:8787`, release 빌드는 `https://moca.vercel.app`(`app/app/build.gradle.kts:35,42` 의 `buildConfigField("String", "SERVER_BASE_URL", …)`, 이 값을 `ApiClient.kt:22` 가 쓴다). 로컬 서버 켜는 명령은 README 「실행 방법 — 서버(로컬)」 절 그대로: `cd server && node local.mjs` (기본 `127.0.0.1:8787`, 에뮬레이터에서는 `10.0.2.2:8787`). `HIVE_API_KEY=... node local.mjs` 로 키를 넣는다. 키가 없으면 `/chat` 은 502 를 돌려주고 앱은 오프라인 음성으로 전환한다 | 노드 없음 — 서버 실행은 터미널 명령이다 |
