## 02-2 기획 배경

**양식에 넣을 본문 (8줄)**

1. 출근길에 계기판에 빨간 ABS 경고등과 노란 타이어 공기압 경고등이 함께 켜졌다. 운전자는 얼마나 급한지, 어디로 가야 하는지 모른다.
2. 첫째, 계기판은 켜졌다는 것만 알려 준다. 더 몰아도 되는지, 무엇부터 해야 하는지는 알려 주지 않는다.
3. 둘째, 알아도 다음 행동이 끊긴다. 정비소를 찾으려면 휴대폰을 꺼내 검색해야 한다. 주행 중에는 할 수 없다.
4. 셋째, 관리한 기록이 남지 않는다. 언제 점검했고 무엇을 고쳤는지 말할 근거가 없다.
5. MOCA 는 차가 주는 값을 읽어 점수와 등급으로 바꾸고, 가장 먼저 할 일 하나만 고른다.
6. 그리고 그 자리에서 이어 준다. 단추 하나로 내비게이션이 가까운 정비소를 찾고, 부품은 QR 로 휴대폰에 넘긴다.
7. 운전자는 누를 필요가 없다. 점검은 시동을 걸 때와 앱을 열 때 스스로 돈다.
8. 점검한 날은 기록으로 쌓이고, 오늘의 순위가 다시 열어 볼 이유가 된다.

**작업용: 근거 상태**

| 페인 포인트 | 통계 근거 | 인터뷰 근거 |
|---|---|---|
| 1. 경고등이 얼마나 급한지 모른다 | 찾지 못함 | 없음(사람이 채운다) |
| 2. 알아도 다음 행동이 끊긴다 | 찾지 못함 | 없음(사람이 채운다) |
| 3. 관리 기록이 남지 않는다 | 찾지 못함 | 없음(사람이 채운다) |

- 「경고등이 켜진 뒤 정비를 미루는 운전자」 설문은 찾지 못했다(`research/06_사업성_통계/수수료_모델_숫자.md`의 「찾지 못함」). 발생률 숫자는 쓰지 않는다.
- 인터뷰 인용을 넣을지는 사람이 정한다. 넣지 않으면 위 8줄만 쓴다.

## 02-3 주요 기능·차량 특화

**핵심: 차 안에서만 읽을 수 있는 값으로 할 일을 고르고, 차 안에서 바로 이어 준다.**

**양식에 넣을 6줄 요약**

1. 차가 주는 부품 값과 경고등을 읽어 카테고리 5개를 100점에서 감점하고, 등급 6단계로 보여 준다(규칙).
2. 점검은 누르지 않는다. 시동(부팅) 때 화면 없이 한 번, 앱을 열 때 한 번 돈다.
3. 감점이 가장 큰 것을 「가장 먼저 할 일」로 고르고, 해결 단추를 하나만 보여 준다.
4. 단추는 감점의 종류를 따라간다. 경고등·오일·타이어는 정비소, 배터리 부족은 충전소, 워셔액은 휴대폰(QR)이다.
5. 말로 물으면 같은 값을 읽어 답한다. 빨간 경고등이면 첫 문장이 정차 안내다.
6. 오늘의 순위와 대전은 같은 점수로 겨루는 놀이다. 등급 계산에는 들어가지 않는다.

| # | 기능 | 무엇인가 | 차라서 가능한 까닭 |
|---|---|---|---|
| ① | 자동 점검과 등급 | 카테고리 5개(동력, 제동·조향, 타이어, 전기, 안전)를 감점해 종합 점수와 등급(S+~D)으로 | Vehicle SDK 가 부품 값과 경고등 상태를 차 안에서 준다 |
| ② | 가장 먼저 할 일과 이어 주기 | 감점이 가장 큰 것 하나와 해결 단추 하나. 내비게이션 검색 화면을 열거나 QR 을 띄운다 | NaviHelper 로 차의 내비게이션에 검색어를 넘긴다. 목적지가 차의 화면에서 바로 잡힌다 |
| ③ | 차에게 묻기 | 말이나 글로 묻고, 도구로 차량 값을 읽어 답한다. 서버가 없어도 기기 안에서 답한다 | 답의 근거가 차 안의 값이고, 주행 중인지를 앱이 안다 |
| ④ | 오늘의 순위와 대전 | 오늘 점수로 매긴 순위, 카테고리 5개를 5라운드로 겨루는 대전 | 내 차의 실제 카테고리 점수가 그대로 쓰인다 |

**이어 주는 길 (실측, 에뮬레이터)**

| 가장 먼저 할 일 | 단추 | 누른 뒤 |
|---|---|---|
| 경고등, 오일, 타이어 등 | 가까운 정비소 안내 | 내비게이션이 「정비소」 검색 결과를 연다. 한 곳을 고르고 「목적지로」를 누르면 길안내가 시작된다(우리 단추 1번 + 내비게이션 2번) |
| 배터리 10% 미만 | 가까운 충전소 안내 | 내비게이션이 「전기차 충전소」 검색 결과를 연다 |
| 워셔액 부족 | 휴대폰으로 부품 보기 | QR 창이 뜬다. QR 은 현대모비스 부품 검색 주소다 |

**모바일로는 안 되는 까닭 3개**

1. **값의 출처가 차 안이다.** 부품 값과 경고등은 차량에서 오고, SDK 는 차 안에서만 읽는다.
2. **이어 주는 곳이 차의 내비게이션이다.** 휴대폰을 꺼내지 않고 차의 화면에서 목적지가 잡힌다.
3. **주행 중인지를 앱이 안다.** 주행 제한 상태를 읽어 화면을 줄이고 말로 돌린다(코드와 선언만 있고, 에뮬레이터에서 실행해 보지는 못했다).

**SDK/API 사용표 (권한·실측 상태)**

| API | 읽는 값·하는 일 | 권한명 | 실측 상태 |
|---|---|---|---|
| `Safety.getTelltalesInfo` | 켜진 경고등 목록·색 정수 | `PRIVATE_CAR_SAFETY` | 호출 성공, `count=0`. 색 정수는 미확인 |
| `Safety.registerTelltales` | 경고등 변경 콜백 | `PRIVATE_CAR_SAFETY` | 등록 OK, 콜백 2회 수신, 값 0개 |
| `Safety.getEngineOilLevelState` | 엔진오일 수준 | `CAR_SAFETY` | 실패. 에뮬레이터에 속성이 없다 → 「측정 불가」로 처리 |
| `Safety.getBrakeFluidLevelState` | 브레이크액 수준 | `CAR_SAFETY` | 실패. 속성 없음 |
| `Tire.getLowTirePressure` | 바퀴별 저압 | `CAR_SAFETY` | 값은 미확인. 바퀴 위치 4개는 확인 |
| `EvBattery.getEvBatteryStateOfCharge` | 배터리 잔량 % | `CAR_ENERGY` | **`SOC value=100` 수신** |
| `NaviHelper.requestNavigationScreen(SearchPlace)` | 내비게이션 검색 화면 열기 | `NAVI_ROUTE` 등 3개 | **검색 결과가 열리고 길안내까지 시작됨** |
| `BOOT_COMPLETED` + 포그라운드 서비스 | 부팅 때 화면 없이 점검 | `RECEIVE_BOOT_COMPLETED` 등 | **재부팅 뒤 점검 로그 확인**(앱을 한 번 연 뒤부터) |

- **읽기 전용.** manifest 에 `CONTROL_` 권한은 0건이다. 앱은 차를 제어하지 않는다.
- **권한 주의.** 공식 문서는 경고등 API 권한을 `signature|privileged`로 적는다. 에뮬레이터 2.1.0 은 같은 권한을 normal 로 선언해 설치가 허용됐다. 실차에서 같은지는 미확인이다.
- 근거: `docs/evidence/G0/report.md`, `docs/evidence/S1~S3/report.md`, `docs/evidence/V9/부팅-때-점검-logcat.txt`.

## 02-4 사용 시나리오

대표 이야기 하나다. 숫자는 데모 시나리오를 에뮬레이터에서 눌러 화면에서 읽은 값이다(`docs/evidence/V9/처음부터-끝까지-눌러-본-기록.md`).

1. **시동을 건다.** 누르지 않아도 점검이 끝나 있다.
2. **홈을 본다.** 등급 B, 종합 75. 「가장 먼저 할 일」에 빨간 글씨로 「ABS 경고등 · 제동·조향 50점 감점」. 오늘 13명 중 9위.
3. **말로 묻는다.** 「이 경고등 뭐야?」 → 「안전한 곳에 정차한 뒤 점검을 받으세요. 지금 ABS 경고등(빨강), 타이어 공기압 경고등(노랑)이 켜져 있어요.」
4. **단추를 누른다.** 「가까운 정비소 안내」 → 내비게이션이 정비소를 찾는다 → 한 곳을 고르고 「목적지로」 → 길안내 시작.
5. **고친 뒤 다시 시동을 건다.** 등급이 오른 순간이 한 번 나온다. 「B → A · 9위 → 5위」.
6. **대전.** 고치기 전에는 2 : 2 동점에 종합 75 대 88 로 졌다. 고친 뒤에는 1 : 0 으로 이긴다.

**다른 길**

- 배터리가 9% 면 할 일이 잔량 부족으로, 단추가 「가까운 충전소 안내」로 바뀐다.
- 워셔액이 부족하면 단추가 「휴대폰으로 부품 보기」로 바뀌고 QR 이 뜬다.
- 문제가 없으면 「오늘도 이상 없어요」와 연속 점검 일수만 보인다. 해결 단추는 없다.
- 날이 바뀌어도 기록이 남는다. 에뮬레이터 날짜를 하루 넘겨 「1일째 → 2일째」를 확인했다.

## 02-5 개발 계획

**양식에 넣을 8줄**

1. 앱은 Android View 와 Pleos 디자인 시스템(`pleos-ds`)으로 만들었다. 화면은 탭 5개다(홈, 상세, 차에게 묻기, 순위·대전, 설정).
2. 차량 값은 Pleos Vehicle SDK 2.3.2 로 읽는다. 읽기 전용이다.
3. 이어 주기는 NaviHelper 3.0.5(내비게이션 검색)와 ZXing(QR)이다.
4. 항목마다 지원 여부를 먼저 확인하고, 지원하지 않는 항목은 계산에서 뺀다. 화면에는 「측정 불가」로 적는다.
5. 서버는 Vercel 함수와 Hive LLM, Upstash Redis 다. 2026-11-12 에 올렸고, 앱에서 음성 답과 점검 요약 올리기·지우기를 확인했다.
6. 서버가 답하지 못하면 음성은 기기 안의 답으로, 대전은 앱 안의 연습 상대로 동작한다. 오늘의 순위는 연습 상대와 매긴다. 화면에 「오프라인 음성」「연습 순위」라고 적는다.
7. 에뮬레이터가 주는 실제 값은 배터리 잔량뿐이라, 나머지는 데모 시나리오 8개(D0~D7)로 보인다. 모든 데모 화면에 「데모 데이터」가 붙는다.
8. 에뮬레이터 한계로 실행해 보지 못한 것은 사실대로 적는다(주행 중 제한, 마이크 입력, 경고등 색 정수).

**지금 상태 (2026-11-12, 실측)**

| 항목 | 결과 |
|---|---|
| 점수 엔진 단위 테스트 | 238 / 238 |
| 앱 단위 테스트 | 86 / 86 |
| 서버 테스트 | 73 / 73 |
| 디자인 시스템 정적 검사 | 0건 |
| 기능별 평가 도구(에뮬레이터에서 화면 글자로 판정) | 39항목 중 통과 28, 실패 0, 수동·부분 11 |
| 처음부터 끝까지 직접 누른 확인 | 11장면 전부 통과, 앱이 죽은 횟수 0 |
| 홈 화면 판독(서로 다른 모델 3) | 등급·급한 문제·누를 단추를 3 중 3 이 맞힘 |

- 수동·부분 11항목은 마이크 음성, 서버 연결 답, 주행 중 제한, 녹화로 재는 시간처럼 이 에뮬레이터에서 잴 수 없는 것이다.
- 홈 화면 판독은 사람 평가가 아니다(`docs/evidence/V9/홈-화면-평가.md`).

**실행해 보지 못한 것**

- 주행 중 제한: 코드와 선언은 있다. 이 에뮬레이터는 주행 상태를 만들 수 없다.
- 마이크 음성 입력: 에뮬레이터에 마이크가 없다. 글자 입력과 질문 단추로 확인했다.
- 경고등 색 정수(빨강·노랑)의 실제 값: 에뮬레이터에서 경고등을 켤 수 없다.
- 앱 화면에서 다른 사용자와 대전하는 모습: 서버에서는 다른 기기의 요약이 상대로 뽑히는 것을 확인했다. 이 에뮬레이터의 실제 값으로는 등급이 나오지 않아 화면에서는 보지 못했다.

**데모 데이터 표기 원칙**

1. 데모 화면 전부에 「데모 데이터」를 붙인다.
2. 데모 기록은 실제 기록과 따로 저장한다.
3. 데모에서도 값은 같은 규칙으로 계산한다. 정해 둔 결과로 덮어쓰지 않는다.
4. 문서·영상·발표에서 데모 장면은 「데모 데이터」라고 말한다.

## 02-6 기대효과·발전

**양식에 넣을 8줄 요약**

1. 돈이 생기는 곳은 「이어 준 건」이다. 차가 문제를 알고, MOCA 가 알려 주고, 정비소나 부품 구매로 이어 준다.
2. 매출 식은 「이어 준 건수 × 건당 수수료」다. 건당 수수료율은 공개된 값을 찾지 못해 (가정)으로만 둔다.
3. 이어 줄 곳은 이미 많다. 정비업체는 36,277개다(2026년 3월, 국토교통 통계누리).
4. 쓸 사람도 이미 차 안에 있다. 현대차·기아 커넥티드 카 국내 가입자는 약 580만 명이다(2024-07-28 기준, 그룹 저널).
5. Pleos Connect 는 2030년까지 약 2,000만 대 탑재가 목표다(현대차그룹 뉴스룸).
6. 예상 MAU 는 「탑재 차량 수 × 설치율 × 월 활성률」로 계산한다. 설치율과 활성률은 (가정)이다.
7. 다시 여는 이유는 두 가지다. 누르지 않아도 도는 점검, 그리고 날마다 바뀌는 오늘의 순위다.
8. 공모전 범위는 1단계(길안내와 휴대폰 넘기기)까지다. 수수료는 제휴가 생긴 뒤의 일이다.

**수익 구조**

```
차가 문제를 앎 → MOCA 가 알려 줌 → 정비소 길안내 / 휴대폰으로 넘김 → 예약·구매
                                                    │
                                         이어 준 건마다 수수료(제휴처가 냄)
```

| 단계 | 내용 | 숫자의 상태 |
|---|---|---|
| 1단계(공모전 범위) | 길안내와 휴대폰 넘기기까지. 수수료 없음 | 동작 확인(에뮬레이터) |
| 2단계 | 정비 예약 제휴. 예약이 이루어지면 건당 수수료 | 수수료율 (가정). 공개 요율을 찾지 못했다 |
| 3단계 | 부품·소모품 구매 제휴. 구매가 이루어지면 수수료 | 수수료율 (가정) |
| 확대 | 쌓인 점검 기록을 중고차 판매 때 관리 증빙으로 | 뼈대만. 약속하지 않는다 |

- 정비 시장 매출 규모는 쓰지 않는다. 자동차 정비만의 매출 통계를 찾지 못했다.
- 건당 수수료율, 전환율, 매출 추정은 넣지 않는다.

**예상 MAU: 탑재 차량 수 × 설치율(a) × 월 활성률(b). a 와 b 는 (가정)이다.**

2030년 2,000만 대 기준(공식 목표).

| a \ b | 30% (가정) | 40% (가정) |
|---|---|---|
| 1% (가정) | 60,000 | 80,000 |
| 2% (가정) | 120,000 | 160,000 |
| 5% (가정) | 300,000 | 400,000 |

- 계산 예: 20,000,000 × 0.02 × 0.40 = 160,000.
- 설치율과 활성률을 잰 값은 없다.

**Retention 장치 (규칙)**

| 장치 | 동작 |
|---|---|
| 자동 점검 | 열지 않아도 시동 때 점검이 돌고 기록이 쌓인다 |
| 오늘의 순위 | 오늘 점수로 날마다 다시 매긴다 |

| 월 시즌 | 매달 1일 관리 50에서 다시 시작한다 |

- D7, D30 목표 숫자는 근거가 없어 적지 않는다.

**확대 계획**

1. **시제품(2026):** 에뮬레이터와 데모 시나리오. 공모전 제출본.

3. **제휴:** 정비 예약, 부품 구매 순으로 이어 주는 곳을 늘린다.

**복제하기 어려운 점**

1. **차 안의 값과 차의 내비게이션.** 둘 다 차량 플랫폼 안에서만 닿는다.
