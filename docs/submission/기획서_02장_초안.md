## 02-2 기획 배경

**양식에 넣을 본문 (8줄)**

1. 출근길에 계기판에 빨간 ABS 경고등과 노란 타이어 공기압 경고등이 함께 켜졌다. 운전자는 얼마나 급한지, 어디로 가야 하는지 모른다.
2. 첫째, 계기판은 켜졌다는 것만 알려 준다. 더 몰아도 되는지, 무엇부터 해야 하는지는 알려 주지 않는다.
3. 둘째, 알아도 다음 행동이 끊긴다. 정비소를 찾으려면 휴대폰을 꺼내 검색해야 한다. 주행 중에는 할 수 없다.
4. 셋째, 관리한 기록이 남지 않는다. 언제 점검했고 무엇을 고쳤는지 말할 근거가 없다.
5. MOCA 는 차가 주는 값을 읽어 구역 5개의 점수와 등급으로 바꾸고, 점수가 낮은 구역부터 감점 원인을 보여 준다.
6. 그리고 그 자리에서 이어 준다. 단추 하나로 차의 내비게이션이 정비소·주유소·충전소 안내를 열고, 용품은 QR 로 휴대폰에 넘긴다.
7. 운전자는 누를 필요가 없다. 점검은 앱을 켤 때 스스로 돈다. 궁금한 것은 말로 묻는다.
8. 점검한 날은 기록으로 쌓이고, 연습 상대와의 대전과 월간랭킹이 다시 열어 볼 이유가 된다.

**작업용: 근거 상태**

| 페인 포인트 | 통계 근거 | 인터뷰 근거 |
|---|---|---|
| 1. 경고등이 얼마나 급한지 모른다 | 찾지 못함 | 없음(사람이 채운다) |
| 2. 알아도 다음 행동이 끊긴다 | 찾지 못함 | 없음(사람이 채운다) |
| 3. 관리 기록이 남지 않는다 | 찾지 못함 | 없음(사람이 채운다) |

- 「경고등이 켜진 뒤 정비를 미루는 운전자」 설문은 찾지 못했다(`research/06_사업성_통계/수수료_모델_숫자.md`의 「찾지 못함」). 발생률 숫자는 쓰지 않는다.
- 인터뷰 인용을 넣을지는 사람이 정한다. 넣지 않으면 위 8줄만 쓴다.

## 02-3 주요 기능·차량 특화

**핵심: 차 안에서만 읽을 수 있는 값으로 상태를 보여 주고, 차 안에서 바로 이어 준다. 기능은 상태관리 · 보이스챗 · 대전하기 세 개다.**

**양식에 넣을 6줄 요약**

1. 차가 주는 부품 값과 경고등을 읽어 구역 5개를 100점에서 감점하고, 등급 6단계로 보여 준다(규칙).
2. 점검은 앱을 켤 때 스스로 돈다. 상태관리의 [다시 점검]으로 고친 뒤 다시 확인한다.
3. **상태관리**: 점수 낮은 구역부터 카드로 보여 주고, 감점 원인마다 해결방안(정비소 방문·용품 구매·직접 해결)을 붙인다.
4. **보이스챗**: 말이나 키보드로 물으면 내 차 값을 근거로 답하고, 확인을 받은 뒤 차량 내비 안내를 시작한다. 빨간 경고등이면 첫 문장이 정차 안내다.
5. **대전하기**: 구역 5개를 한 라운드씩 연습 상대와 겨룬다. 진 구역은 «이 차만큼 관리하려면» 무엇을 고치면 되는지 알려 준다.
6. 월간랭킹은 연습 상대 12명과 나의 순위다. 대전 결과는 전적에만 쌓이고 등급 계산에는 들어가지 않는다.

| # | 기능 | 무엇인가 | 차라서 가능한 까닭 |
|---|---|---|---|
| ① | 상태관리 | 구역 5개(동력, 제동·조향, 타이어, 전기, 안전)를 감점해 종합 점수와 등급(S+~D)으로. 2D 자동차 그림에 구역·바퀴 상태를 색으로 보이고, 카드를 펼치면 감점 원인과 해결방안. [정비소 찾기]·[주유소 안내]·[충전소 안내], 용품 QR, [다시 점검], [AI에게 물어보기] | Vehicle SDK 가 부품 값과 경고등 상태를 차 안에서 준다 |
| ② | 보이스챗 | 말이나 키보드로 묻고, 도구로 차량 값을 읽어 답한다. «지금 내 차» 요약 카드와 근거 한 줄. 내비 조작 전 확인 카드, 먼저 제안, 경유지(최대 2곳), 안내 취소. 서버가 안 되면 기기 안의 답 | 답의 근거가 차 안의 값이고, 주행 중인지를 앱이 안다 |
| ③ | 대전하기 | 구역 5개를 한 라운드씩 겨룬다. [대전 시작]을 누르면 두 차가 부딪치는 3D 영상이 나오고 진 쪽 차가 부서진다(이긴 쪽은 멀쩡). 결과 뒤 «이 차만큼 관리하려면»과 [해결하러 가기]. 월간랭킹과 이번 달 관리 요약, [질문하기] | 내 차의 실제 구역 점수가 그대로 쓰인다 |

앱을 켜면 먼저 **앱 시작 화면**이 자동 점검 결과를 보여 준다(등급·종합, 켜진 경고등, 구역 5개 점수, 조치 항목 최대 3개, 연료·배터리 잔량, 측정 불가 수). 1분 뒤 메인으로 넘어가고, 정차 중 빨간 경고등이 있으면 머문다. 주행 중에는 등급·경고등만 보이고 바로 메인으로 넘어가며, 빨간 경고등이면 음성으로 정차를 안내한다.

**첫 실행.** 동의 3개(차량 상태로 점수 계산 / 음성 질문과 점수 요약을 서버를 거쳐 AI에 전송 / 대전 상대에게 닉네임·등급·점수 표시)에 모두 동의해야 쓸 수 있다. 하나라도 거절하면 앱이 종료된다. 서버로 가는 것은 AI 질문(`POST /chat`) 하나이고, 위치·차대번호·타이어 공기압 수치·점검 기록 원본은 보내지 않는다. 점검 기록은 기기 안에만 있고 실제 기록은 90일 보관한다.

**내비 연동: 동작한다. 실제 모드와 데모 모드가 다르다.**

Pleos NaviHelper SDK 3.0.5 에는 «근처 장소 목록»을 돌려주는 함수가 없다(확인됨). 그래서 둘로 나뉜다.

| 모드 | 하는 일 | 상태 |
|---|---|---|
| 실제 모드 | 차의 내비게이션 **검색 화면**을 연다(정비소·주유소 검색, 충전소는 내비의 «가까운 충전소» 화면). 운전자가 결과에서 한 곳을 고르고 「목적지로」를 누르면 길안내가 시작된다(우리 단추 1번 + 내비게이션 2번) | 검색 화면이 열리는 것을 에뮬레이터에서 확인(`docs/evidence/S3`). 결과를 고른 뒤 길안내가 시작되는 것은 옛 앱의 확인 기록(`docs/evidence/V9/처음부터-끝까지-눌러-본-기록.md`)에 있다. 지금 앱 화면으로 다시 찍은 기록은 없다(미확인) |
| 데모 모드 | 앱에 넣은 **장소 목록의 좌표**로 안내·경유지(최대 2곳)·안내 취소를 한다 | 에뮬레이터에서 좌표 안내(`requestRoute`)를 요청한 뒤 내비가 안내 시작 알림을 보내는 것까지 확인(`docs/evidence/S1`은 같은 호출의 시험 앱 기록) |

**용품 QR.** 타이어 저압은 휴대용 타이어 공기 주입기, 워셔액 부족은 워셔액의 QR 이미지를 보여 준다. 미리 만든 이미지 2개이고 상품명을 지정한 쿠팡 검색 주소다(불스원 레인OK 에탄올 3in1 코팅워셔액 1.8L, 샤오미 미지아 무선 공기주입기 2). **제휴 연동 예정**이며 수수료 문구는 넣지 않았다. 상품은 팀이 고른 것이다.

**점수 기준은 어디서 왔나 (최종정리 2.6절)**

API 는 «엔진오일이 부족하다» 같은 **상태**까지만 알려 준다. 그 상태가 몇 점인지는 알려 주지 않는다. 그래서 감점 숫자는 팀이 정한 **설계 판단**이다.

| 기준의 부분 | 출처 | 외부 근거 |
|---|---|---|
| 받는 항목 10개와 상태 종류(정상/부족/심각 부족/과다/오류) | Pleos Vehicle SDK 2.3.2 | 있음 (API) |
| 타이어 저압 여부 | 차가 정한 바퀴별 저압 기준값과 현재 공기압 비교 | 있음 (API, 기준은 차가 정함) |
| 경고등 빨강 −50 > 노랑 −25 (**순서**) | 팀 점수 엔진 | 있음 (ISO 2575 의 색 의미) |
| 감점 숫자(−50, −40, −25, −20, −10), 잔량 10% 기준, 같은 원인은 한 번만 감점 | 팀 점수 엔진 | **없음 (설계 판단)** |

**PT 에서 설명하는 법**

- "어떤 항목을 어떤 상태로 받는지는 차량 API 를 그대로 따랐다."
- "빨강을 노랑보다 크게 감점한 것은 차량 경고등 국제 표준(ISO 2575)의 색 의미를 따랐다."
- "그 밖의 숫자 크기는 위험도 순서를 정해 점수로 옮긴 설계다. 정비 규격에서 나온 값은 아니다."

**모바일로는 안 되는 까닭 3개**

1. **값의 출처가 차 안이다.** 부품 값과 경고등은 차량에서 오고, SDK 는 차 안에서만 읽는다.
2. **이어 주는 곳이 차의 내비게이션이다.** 휴대폰을 꺼내지 않고 차의 화면에서 목적지 찾기가 시작된다.
3. **주행 중인지를 앱이 안다.** 주행 제한 상태를 읽어 화면을 줄이고, 키보드 입력을 막고, 말로 돌린다(코드와 선언만 있고, 에뮬레이터에서 실행해 보지는 못했다).

**SDK/API 사용표 (권한·실측 상태)**

| API | 읽는 값·하는 일 | 권한명 | 에뮬레이터(Pleos Connect v2.1.0) 실측 상태 |
|---|---|---|---|
| `Safety.getTelltalesInfo` | 켜진 경고등 목록·색 정수 | `PRIVATE_CAR_SAFETY` | 호출 성공, `count=0`. 색 정수는 미확인 |
| `Safety.registerTelltales` | 경고등 변경 콜백 | `PRIVATE_CAR_SAFETY` | 등록 OK, 콜백 2회 수신, 값 0개 |
| `Safety.getEngineOilLevelState` | 엔진오일 수준 | `CAR_SAFETY` | 속성이 없어 읽히지 않음 → 「측정 불가」 |
| `Safety.getTransmissionOilLevelState` | 변속기오일 수준 | `CAR_SAFETY` | 속성이 없어 읽히지 않음 |
| `Safety.getBrakeFluidLevelState` | 브레이크액 수준 | `CAR_SAFETY` | 속성이 없어 읽히지 않음 |
| `Safety.hasLowWasherFluidWarning` | 워셔액 부족 | `CAR_SAFETY` | 속성이 없어 읽히지 않음 |
| `Safety.hasSeatAirbagBeenDeployed`, `hasPowerDownWarningIndicator` | 에어백 전개, 파워다운 경고 | `CAR_SAFETY` | 미확인 |
| `Tire.getLowTirePressure`, `Tire.getTirePressure` | 바퀴별 저압 / 현재 공기압(저압 판정에만 쓰고 점수·서버에 쓰지 않음) | `CAR_SAFETY` | 현재 공기압 속성(`TIRE_PRESSURE`)이 없어 타이어는 「측정 불가」. 바퀴 위치 4개는 확인 |
| `Fuel.getFuelPercent` | 연료 잔량 % | `CAR_ENERGY` | 속성이 없어 읽히지 않음 |
| `EvBattery.getEvBatteryStateOfCharge` | 배터리 잔량 % | `CAR_ENERGY` | **`SOC value=100` 수신** |
| `Odometer.getCurrentDistanceDriven` | 누적 주행거리(표시용) | `CAR_DRIVE` | 미확인. 단위도 미확인 |
| `NaviHelper` (검색 화면 열기, 좌표 안내 요청) | 내비 안내 | `NAVI_ROUTE` 등 3개 | 위 «내비 연동» 표 |

- **그래서 에뮬레이터의 실제 모드는 등급이 나오지 않는다.** 읽을 수 있는 구역이 3개 미만이라 「이 차는 읽을 수 있는 항목이 적어 등급을 낼 수 없어요」가 나온다. 화면 확인은 데모 모드(D0~D7)로 한다.
- **읽기 전용.** manifest 에 `CONTROL_` 권한은 0건이다. 앱은 차를 제어하지 않는다.
- **권한 주의.** 공식 문서는 경고등 API 권한을 `signature|privileged`로 적는다. 에뮬레이터 2.1.0 은 같은 권한을 normal 로 선언해 설치가 허용됐다. 실차에서 같은지는 미확인이다.

## 02-4 사용 시나리오

대표 이야기 하나다. 데모 D3 기준이다. 숫자는 점수 엔진과 앱 단위 테스트가 같은 값으로 검산한다(계산). release APK 를 깨끗한 에뮬레이터에 깔아 이 순서로 눌러 본 기록이 있다(2026-11-14, 확인 17 / 17, `docs/evidence/V12`).

1. **앱을 켠다.** 앱 시작 화면에서 점검이 자동으로 돈다. 등급 B, 종합 75. 빨간 경고등 ABS. 조치 항목은 「ABS 경고등 −50」 「타이어 공기압 경고등 −25」 두 줄. 정차 중 빨간 경고등이라 1분이 지나도 메인으로 넘어가지 않는다.
2. **메인을 본다.** 「B · 75」, 빨간 「주의 2」, 「방금 점검 기준」. 기능 단추 3개.
3. **상태관리를 연다.** 2D 그림에서 제동·조향이 빨강, 타이어가 노랑. 구역 점수 100 / 50 / 75 / 100 / 100. ABS 상세에 [정비소 찾기], 타이어 상세에 공기 주입기 QR 과 [정비소 찾기].
4. **말로 묻는다.** ABS 상세의 [AI에게 물어보기]로 보이스챗에 넘어가면 ABS 카드와 추천 질문 3개가 보인다. 「이 경고등 뭐야?」의 첫 문장은 「안전한 곳에 정차한 뒤 점검을 받으세요」다.
5. **내비 안내를 요청한다.** 「가까운 정비소 안내해줘」 → 확인 카드 → [안내 시작]. 데모 모드는 장소 목록의 좌표로 안내를 시작한다. 실제 모드는 내비의 검색 화면이 열린다.
6. **대전한다.** 상대 라이벌드라이버와 라운드 무 · 패 · 패 · 승 · 승, 2 : 2, 종합 75 대 88 로 진다. 「이 차만큼 관리하려면」에 ABS 경고등(제동·조향)과 타이어 공기압(타이어)이 뜨고, 앞선 구역은 전기·안전이다.
7. **고친다.** [해결하러 가기]로 상태관리에 돌아가 데모 전용 [ABS 해결 (데모)]를 누르면 관리 58, 「A · 83」이 된다.
8. **월간랭킹을 본다.** 연습 상대 12명과 나, 13명 중 9위. 1위 새벽드라이버 97점과 22점 차이. [질문하기]를 누르면 이번 달 관리 요약을 가지고 보이스챗으로 넘어간다.

**다른 길**

- 배터리가 9% 면 조치 항목이 잔량 부족으로, 단추가 [충전소 안내]로 바뀐다.
- 워셔액이 부족하면 해결방안이 용품 구매로 바뀌고 워셔액 QR 이 뜬다.
- 해결할 항목이 없으면 「지금 해결할 항목이 없어요」가 보인다.
- 주행 중에는 상태관리·대전하기에 들어갈 수 없다. 대신 보이스챗으로 정비소 안내를 요청한다.

## 02-5 개발 계획

**양식에 넣을 8줄**

1. 앱은 Android View 와 Pleos 디자인 시스템(`pleos-ds`)으로 만들었다. 하단 탭은 홈·상태관리·보이스챗·대전하기·설정이고, 앱 시작 화면과 월간랭킹 화면이 더 있다.
2. 차량 값은 Pleos Vehicle SDK 2.3.2 로 읽는다. 읽기 전용이다.
3. 이어 주기는 NaviHelper 3.0.5(실제 모드는 내비 검색 화면, 데모 모드는 장소 목록의 좌표)와 미리 만든 QR 이미지 2개다.
4. 항목마다 지원 여부를 먼저 확인하고, 지원하지 않는 항목은 계산에서 뺀다. 화면에는 「측정 불가」로 적는다.
5. 서버는 Vercel 함수와 Hive LLM 이다. 앱이 서버로 보내는 것은 AI 질문(`POST /chat`) 하나다. 2026-11-12 에 올렸고, 그때 앱(이전 버전)에서 음성 답을 확인했다.
6. 서버가 답하지 못하면 보이스챗은 기기 안의 답으로 동작한다(길 안내 포함). 점검 기록은 기기 안 파일에만 둔다.
7. 에뮬레이터가 주는 실제 값은 배터리 잔량뿐이라, 나머지는 데모 시나리오 8개(D0~D7)로 보인다.
8. 에뮬레이터 한계로 실행해 보지 못한 것은 사실대로 적는다(주행 중 제한, 마이크 입력, 경고등 색 정수, 실차).

- 에뮬레이터 실제 모드의 등급: 엔진오일·브레이크액·변속기오일·워셔액·연료·타이어 현재 공기압 속성이 없어 등급이 나오지 않는다. 데모 모드로 본다.
- 주행 중 제한: 코드와 선언은 있다. 이 에뮬레이터는 주행 상태를 만들 수 없다.
- 마이크 음성 입력: 에뮬레이터에 마이크가 없다. 글자 입력과 질문 단추로 확인했다.

**범위 밖으로 둔 것.** 실제 사용자와의 대전, 서버 순위, 점수 요약의 서버 업로드는 2차 PT 범위 밖이다. 대전 상대와 월간랭킹은 연습 상대(앱 안)뿐이다.

**데모 시나리오 원칙**

1. 데모 모드에서는 설정에서 고른 시나리오 값을 쓴다(차량 값, 장소 목록). 대전 상대와 월간랭킹 상대는 화면에 「연습 상대」로 나온다.
2. 데모 기록은 실제 기록과 따로 저장한다.
3. 데모에서도 값은 같은 규칙으로 계산한다. 승패를 정해 둔 결과로 덮어쓰지 않는다(상대의 값만 시나리오별로 고정이다).
4. 문서·영상·발표에서 데모 장면은 「데모 시나리오」라고 말한다.

## 02-6 기대효과·발전

**양식에 넣을 8줄 요약**

1. 돈이 생기는 곳은 「이어 준 건」이다. 차가 문제를 알고, MOCA 가 알려 주고, 정비소나 부품 구매로 이어 준다.
2. 매출 식은 「이어 준 건수 × 건당 수수료」다. 건당 수수료율은 공개된 값을 찾지 못해 (가정)으로만 둔다.
3. 이어 줄 곳은 이미 많다. 정비업체는 36,277개다(2026년 3월, 국토교통 통계누리).
4. 쓸 사람도 이미 차 안에 있다. 현대차·기아 커넥티드 카 국내 가입자는 약 580만 명이다(2024-07-28 기준, 그룹 저널).
5. Pleos Connect 는 2030년까지 약 2,000만 대 탑재가 목표다(현대차그룹 뉴스룸).
6. 예상 MAU 는 「탑재 차량 수 × 설치율 × 월 활성률」로 계산한다. 설치율과 활성률은 (가정)이다.
7. 다시 여는 이유는 두 가지다. 앱을 켤 때마다 도는 점검과 쌓이는 기록, 그리고 연습 상대와의 대전·월간랭킹이다.
8. 공모전 범위는 1단계(내비 안내와 휴대폰 넘기기)까지다. 수수료는 제휴가 생긴 뒤의 일이다.

**수익 구조**

```
차가 문제를 앎 → MOCA 가 알려 줌 → 정비소 내비 안내 / 휴대폰으로 넘김(QR) → 예약·구매
                                                    │
                                         이어 준 건마다 수수료(제휴처가 냄)
```

| 단계 | 내용 | 숫자의 상태 |
|---|---|---|
| 1단계(공모전 범위) | 내비 안내와 휴대폰 넘기기(QR)까지. 수수료 없음 | 동작 확인(에뮬레이터). QR 은 상품명 지정 쿠팡 검색 주소이고 제휴 연동 예정 |
| 2단계 | 정비 예약 제휴. 예약이 이루어지면 건당 수수료 | 수수료율 (가정). 공개 요율을 찾지 못했다 |
| 3단계 | 부품·소모품 구매 제휴. 구매가 이루어지면 수수료 | 수수료율 (가정) |
| 확대 | 쌓인 점검 기록을 중고차 판매 때 관리 증빙으로 | 뼈대만. 약속하지 않는다 |

**쓸 수 있는 숫자와 출처**

| 항목 | 값 | 출처 |
|---|---|---|
| 정비업체 수 | 36,277개 (2026년 3월) | 국토교통 통계누리 「자동차관리사업자업체현황(분기)」 |
| 커넥티드 카 국내 가입자 | 약 580만 명 (2024-07-28 기준) | 현대차그룹 저널 |
| Pleos Connect 탑재 목표 | 2030년까지 약 2,000만 대 | 현대차그룹 뉴스룸 |
| 국내 자동차 누적 등록 | 26,676천 대 (2026-06 말) | 국토교통부 보도자료 |
| 엔진오일 교체 주기 | 10,000 km 또는 12개월 | 현대 취급설명서(통상 조건) |

- 정비 시장 매출 규모는 쓰지 않는다. 자동차 정비만의 매출 통계를 찾지 못했다.
- 건당 수수료율, 전환율, 매출 추정은 넣지 않는다.

**예상 MAU: 탑재 차량 수 × 설치율(a) × 월 활성률(b). a 와 b 는 (가정)이다.**

2030년 2,000만 대 기준(공식 목표).

| a \ b | 30% (가정) | 40% (가정) |
|---|---|---|
| 1% (가정) | 60,000 | 80,000 |
| 2% (가정) | 120,000 | 160,000 |
| 5% (가정) | 300,000 | 400,000 |

- 계산 예: 20,000,000 × 0.02 × 0.40 = 160,000.
- 설치율과 활성률을 잰 값은 없다.

**Retention 장치 (규칙)**

| 장치 | 동작 |
|---|---|
| 자동 점검 | 앱을 켤 때마다 점검이 돌고 기록이 쌓인다(점검한 날 = 앱을 켠 날) |
| 월간랭킹 | 이번 달 종합 점수 순위. 연습 상대 12명과 나. 매달 1일 새로 시작. 동점이면 관리 점수가 높은 쪽이 위 |
| 연속 점검 | 점검한 날 +2, 7일 연속 +5 |
| 해소 보너스 | 감점 원인이 사라지면 원인 묶음당 +5(하루 최대 +10) |
| 월 시작 | 매달 1일 관리 50에서 다시 시작한다. 마지막 점검 후 14일이 지나면 하루 −1 |
| 대전 | 연습 상대와 구역별로 겨루고, 진 구역의 해결 방법을 알려 준다 |

- D7, D30 목표 숫자는 근거가 없어 적지 않는다.

**확대 계획**

1. **시제품(2026):** 에뮬레이터와 데모 시나리오. 공모전 제출본.
2. **실차 확인:** 실차에서 권한과 경고등 색 값을 확인한다. 실제 사용자 순위·대전과 점수 요약 업로드는 그 뒤의 일이고 2차 PT 범위 밖이다.
3. **제휴:** 정비 예약, 부품 구매 순으로 이어 주는 곳을 늘린다.

**복제하기 어려운 점**

1. **차 안의 값과 차의 내비게이션.** 둘 다 차량 플랫폼 안에서만 닿는다.
2. **쌓이는 점검 기록.** 기록은 시간이 있어야 생긴다.
