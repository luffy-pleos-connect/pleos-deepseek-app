## 02-1 한 줄 소개 (≤50자)

세 안 모두 50자 이내다. 글자 수는 공백 포함이다.

| 안 | 문장 | 글자 수 |
|---|---|---|
| **A (추천)** | 차가 알려 주는 부품 상태, 점수와 등급으로 키우는 관리 파트너 | 35자 |
| B | 경고등이 켜지기 전에, 차가 알려 주는 내 차 건강 파트너 | 32자 |
| C | 부품은 점수로, 관리는 등급으로. 차와 대화하는 차량 관리 앱 | 34자 |

**추천: A안.** 이유는 세 가지다.
1. "차가 알려 주는"이 차량 데이터 사용을 첫 구절에 둔다. 심사 4항목 중 차량특화성이 먼저 읽힌다.
2. "점수와 등급"이 앱의 결과물을 바로 말한다. B안은 결과물이 없다.
3. "관리 파트너"가 앱 이름 MOCA의 문구(C-01)와 같다.

B안은 공포 소구가 앞에 온다. C안은 두 문장이라 한 줄 소개로 길다.

## 02-2 기획 배경

**양식에 넣을 본문 (9줄)**

1. 출근길에 계기판에 빨간 ABS와 노란 TPMS 경고등이 함께 켜졌다. 운전자는 급한 정도를 몰라 차를 세웠다.
2. 첫째, 계기판은 켜짐만 알려 준다. 언제 정비해야 하는지, 더 몰아도 되는지는 알려 주지 않는다.
3. 둘째, 부품 상태가 흩어져 있다. 오일은 정비소, 타이어는 주유소, 배터리는 겨울에만 본다.
4. 셋째, 관리 이력이 남지 않는다. 무엇을 언제 해결했는지 말할 근거가 없다.
5. "계기판과 휴대폰 검색이면 되지 않나"라는 반론에는 세 가지로 답한다.
6. 주행 중에는 검색할 수 없다. MOCA는 리스너로 받은 경고를 음성으로 먼저 설명한다.
7. 흩어진 상태를 점수 하나와 할 일로 묶는다. 부품 5개를 100점 기준으로 계산해 등급 하나로 보여 준다.
8. 관리 이력이 시즌마다 쌓인다. 매달 관리 50에서 다시 시작하고, 지난 시즌 등급이 남는다. 검색은 이력을 남기지 않는다.
9. 시장은 이미 크다. 국내 누적 등록은 26,676천 대다(2026-06 말, 국토교통부). Pleos 탑재 목표는 2030년 약 2,000만 대다.

**작업용: 근거 상태 (양식에는 인터뷰 인용으로 교체)**

| 페인 포인트 | 통계 근거 | 인터뷰 근거 |
|---|---|---|
| 1. 경고등의 급한 정도를 모른다 | 확인 안 됨 | 인터뷰 예정(11/10~11) |
| 2. 부품 상태가 흩어져 있다 | 확인 안 됨 | 인터뷰 예정(11/10~11) |
| 3. 관리 이력이 남지 않는다 | 확인 안 됨 | 인터뷰 예정(11/10~11) |

- 확보된 통계는 시장 규모뿐이다. 페인 포인트 발생률 통계로 쓰지 않는다.
- 시장 규모 출처 두 건은 02-6 표에 URL과 함께 있다.
- 인터뷰(QM-08)가 끝나면 위 표의 오른쪽 칸을 익명 인용으로 바꾼다.
- 반론 답 3개에 대한 동의 비율(UF-11: 5명 중 3명 이상)도 그때 함께 적는다.

## 02-3 주요 기능·차량 특화

**핵심은 "차 안에서만 읽을 수 있는 값을 점수와 대화로 바꾼다"는 것이다.**

**양식에 넣을 6줄 요약**

1. 차가 부품 상태를 알려 준다. 앱은 100점 기준 점수와 등급 6단계로 보여 준다(규칙).
2. 경고등은 리스너로 받아 홈 배지에 즉시 반영한다. 폴링하지 않는다.
3. 같은 신호를 음성 상담의 근거로 써서, 주행 중에도 화면 없이 상태를 확인한다.
4. 카테고리 5개를 대전 라운드로 돌려, 관리할 이유를 하나 더 만든다.
5. 위 세 기능은 휴대폰 앱으로 같은 값을 만들 수 없다. 값의 출처가 차 안이기 때문이다.
6. 다른 앱과 달리 점수·이력·대전을 한 흐름으로 묶는다. Gleo AI 문서에는 이 셋이 없다.

| # | 기능 | 무엇인가 | 해결하는 문제 | 차라서 가능한 이유 |
|---|---|---|---|---|
| ① | 부품 점수·등급 | 카테고리 5개(동력, 제동·조향, 타이어, 전기, 안전)를 100점에서 감점해 등급 6단계(S+~D)로 표시 | 흩어진 상태를 한 숫자로 판단 | Vehicle SDK가 부품 원본값과 경고등 상태를 차 안에서 직접 준다 |
| ② | 경고등 실시간 배지 | `registerTelltales` 리스너 콜백으로 홈의 "주의 n" 배지를 즉시 갱신(폴링 없음) | 경고등이 켜진 순간을 놓친다 | 경고등은 차량 내부 이벤트로 오고, SDK 리스너로 받는다 |
| ③ | 음성 차량 상담(도구 호출) | 질문 → LLM이 차량 도구 3~7개 호출 → 도구 결과에 근거한 답을 음성·글자로 | 주행 중 화면 조작 없이 상태 확인 | 도구가 읽는 값이 차 안 실데이터이고, 주행 제한 상태를 앱이 안다 |
| ④ | 부품 라운드 대전 | 카테고리 5개를 5라운드로 비교, 승/무/패 판정(등급 미반영) | 관리할 이유가 약하다 | 내 차의 실제 카테고리 점수가 대전 카드가 된다 |

**모바일로는 안 되는 이유 3개**

1. **값의 출처가 차 안이다.** 부품 상태는 차량 VHAL에서 오고, SDK는 차 안 로컬 IPC로만 읽는다. 휴대폰 앱은 같은 원본값에 접근할 수 없다.
2. **즉시성이 리스너에 달려 있다.** 경고등 배지는 차량 이벤트 콜백으로 갱신한다. 폴링하는 휴대폰 앱은 켜진 순간을 놓치고 배터리만 쓴다.
3. **주행 맥락을 앱이 안다.** 주행 중에는 조작을 줄이고 음성으로 돌린다. 이 판단은 차량의 주행 제한 상태(CarUxRestrictions)를 읽어야 한다.

**기존 앱·Gleo AI 대비 차별점 3개**

1. **부품 상태의 점수화·등급화.** Pleos 공식 Gleo AI 소개 페이지를 확인했다(2026-11-10). 그 페이지는 음성 대화와 패널 표시를 설명한다. 부품 점수·등급·경고등 이력 기능은 거기서 확인되지 않았다.
2. **경고등 리스너를 답변 근거로 연결.** Gleo AI 문서는 대화 상태와 패널 표시를 다룬다. 경고등 색·종류를 읽어 답변 첫 문장을 정하는 구조는 확인되지 않았다.
3. **시즌제 관리 이력 + 부품 대전.** 월 시즌, 7일 연속 보너스, 해소 보너스, 비동기 대전을 한 앱에 묶는다. Gleo AI 문서에 해당 기능은 확인되지 않았다.
- **한계 표기:** 현대·기아 순정 앱의 차량 상태 기능 비교(QM-10)는 아직 안 했다. 공식 자료 확인 필요. 확인 전에는 "공식 자료 확인 필요"로만 쓴다.

**SDK/API 사용표 (권한·실측 상태)**

| API | 읽는 값 | 권한명 | 실측 상태 |
|---|---|---|---|
| `Safety.getTelltalesInfo` | 켜진 경고등 목록·색 정수 | `PRIVATE_CAR_SAFETY` | 호출 성공, `count=0` (실측). 색 정수는 미확인 |

| `Safety.getBrakeFluidLevelState` | 브레이크액 수준 | `CAR_SAFETY` | 실패. 속성 미등록 (실측). 반환형 `OilLevelState`는 AAR로 확인 |

## 02-4 사용 시나리오

**J1. 첫 실행은 탭 세 번으로 첫 등급에 닿는다.** 동의 → 닉네임(건너뛰면 자동 이름) → [점검하고 첫 등급 받기] 순서다. 점검 목표 시간은 3초 이내다(설계 목표). 정상 차는 85점 A로 나온다(계산).

**J2. 경고등이 켜진 날, 앱은 등급을 낮추고 할 일을 남긴다.** 홈 배지가 빨간 "주의 2"로 바뀌고, "이 경고등 뭐야?"라고 물으면 도구 칩이 켜진다. 첫 답은 "안전한 곳에 정차한 뒤 점검을 받으세요"다. 점검 결과는 75점 B다. ABS를 해결한 뒤 재점검하면 관리 +5로 83점 A가 된다(데모 D3 계산값).

**J3. 매일 루틴은 점수 2점과 7일 보너스로 유지된다.** 시동 뒤 홈에서 점검을 누르면 +2가 붙는다. 7일째에는 "+5"가 함께 붙는다. 감쇠는 마지막 점검일부터 14일이 지난 뒤 하루 −1로 시작한다.

**J4. 대전은 정차 중에만 열리고, 결과는 등급에 반영되지 않는다.** 서버가 상대를 1초 안에 고른다(설계 목표). 5라운드는 0.6초 간격으로 공개된다(설계 값). 서버가 끊기면 앱 안 시드와 "연습 상대"로 바뀐다. 대전은 재미 장치이고 등급 계산에는 들어가지 않는다.

**J5. 주행 중에는 화면 대신 음성이 답한다.** 타일을 누르면 제한 안내 한 줄과 [음성으로 물어보기]만 남는다. "내 차 등급 몇이야?"라고 물으면 도구 결과의 숫자를 그대로 읽는다. 답은 2문장 이내다.

## 02-5 개발 계획

**양식에 넣을 8줄**

1. 앱은 Android View와 Pleos 디자인 시스템(`pleos-ds`)으로 만든다. 화면은 7개다.
2. 차량 값은 Pleos Vehicle SDK 2.3.2로 읽는다. 읽기 전용이고 제어 권한은 0건이다.
3. 서버는 Vercel 함수와 Hive LLM이다. 저장은 Upstash Redis를 쓴다.
4. 모든 항목은 `check*Capabilities`로 지원 여부를 먼저 확인한다. 미지원은 계산에서 뺀다.
5. 차량 값 읽기는 항목별 비동기 콜백이고, 항목당 1.5초 제한을 둔다.
6. 경고등은 `registerTelltales` 리스너로 받는다. 폴링하지 않는다.
7. 실연동은 코드 구현과 SOC 실값 수신까지 확인했다. 경고등 색 정수는 미확인이다.
8. 그래서 화면과 계산은 트랙 A/B 두 갈래로 약속한다. 데모는 배지로 구분한다.

**구조는 "앱 + 차량 SDK + 얇은 서버"다.**

| 계층 | 구성 | 역할 | 상태 |
|---|---|---|---|
| 앱 | Android View(XML) + `Theme.PleosConnect` + `pleos-ds` 모듈, Fragment 7개 | 화면·점수 계산·로컬 저장(Room·DataStore) | 미착수(설계 완료) |
| Vehicle SDK | Pleos Vehicle 2.3.2 (읽기 전용) | 부품 값·경고등 리스너·capability | **연동 코드 구현·에뮬레이터 실행 완료** |
| 서버 | Vercel 함수 + Hive `deepseek-v4.1-flash` (OpenAI 호환 `/chat/completions`) | 음성 상담 도구 호출, 대전 상대 | 코드·테스트 로컬 완료, 배포 전 |
| 저장소 | Upstash Redis (REST, SDK 없음) | 스냅샷·상대 풀·한도 | 코드 완료, 배포 전 |

**SDK/API 사용표는 도메인과 권한 단위로 적는다.** API 이름과 값은 02-3 표에 있다.

| 도메인 | capability 조회 | 필요한 권한 | 실측 상태 |
|---|---|---|---|
| Safety | `checkTelltalesCapabilities` | `PRIVATE_CAR_SAFETY` | `accessType=READ` (실측) |
| Safety(값) | 항목별 비동기 콜백, 항목당 1.5초 제한 | `CAR_SAFETY` | 오일·브레이크액 실패(속성 없음) |
| Tire | `checkWheelAreaCapabilities` | `pleos.car.permission.CAR_SAFETY` | WheelArea 4개 (실측) |
| EvBattery | 도메인 capability 조회 | `pleos.car.permission.CAR_ENERGY` | 미확인 |
| Fuel | 도메인 capability 조회 | `pleos.car.permission.CAR_ENERGY` | 미확인 |
| Odometer | 도메인 capability 조회 | `pleos.car.permission.CAR_DRIVE` | 미확인 |
| CarInfo | 도메인 capability 조회 | `pleos.car.permission.CAR_INFO` | 미확인 |

- 순서는 고정이다. capability 확인 → 미지원 제외 → 값 읽기 → 화면·계산 반영.
- 나머지 네 도메인의 capability 함수명은 아직 모른다. 그래서 "도메인 capability 조회"로 적었다. 추측한 이름은 쓰지 않는다.

**실연동 상태는 사실대로 적는다.** 아래 문장을 앱·문서·영상에서 그대로 쓴다.

> Vehicle SDK 연동 코드 구현 완료, 에뮬레이터에서 배터리 SOC 실값(100) 수신·경고등 리스너 콜백 수신 확인. 경고등 색 정수 매핑은 에뮬레이터 Virtual Console 제약으로 미확인.

- 위 문장의 근거는 `docs/evidence/G0/report.md`와 실행 로그다.
- 콜백은 등록 OK 뒤 2회 왔고, 실린 경고등은 0개였다(경고등 꺼진 상태).
- 오일·브레이크액은 에뮬레이터에 속성이 없어 읽기 자체가 안 된다.
- AAR로 시그니처만 확정했다. `getColor()`는 Int를 돌려주고 `TelltaleColor`는 6종이다. 색 정수 실값은 없다.

**개발 범위는 트랙 A/B로 나눈다.**
- 트랙 A(실연동): 실제 SDK 값으로 점검·점수·시즌·상태관리를 한다. 경고등 배지·서버 실사용자 대전·주행 제한도 실제 값으로 동작한다.

- 공통 약속: 점검·점수·시즌·상태관리·보이스 도구 3개·연습 상대 대전·동의·데이터 삭제.
- 현재 상태: G0(실연동 스파이크) **부분 통과**. 실값 파이프라인은 증명됐고, 경고등 색 정수만 미확인이다.

측정 완료(2026-11-10).

## 02-6 기대효과·발전

*양식에는 아래 10줄 요약과 시장·MAU·비용 표를 넣는다. 민감도 표와 Retention 표는 별지로 옮긴다.*

**양식에 넣을 10줄 요약**

1. 국내 누적 등록은 26,676천 대다(2026-06 말, 국토교통부).
2. Pleos Connect 탑재 목표는 2030년 약 2,000만 대다(현대차그룹 뉴스룸).
3. 목표 시장은 Pleos 탑재 차량이다. MAU = 탑재 수 × 설치율 × 월 활성률로 계산한다.
4. 2028년 700만 대, 설치율 2%(가정), 활성률 40%(가정)면 56,000명이다.
5. 설치율·활성률의 실측 근거는 아직 없다. 사용성 테스트 뒤 다시 본다.
6. Retention은 감쇠, 7일 연속, 해소 보너스, 월 시즌, 대전으로 붙잡는다(규칙).
7. 목표는 D7 40%, D30 20%다(가정).
8. LLM 비용은 22일 최대 약 $4다(계산). Vercel·Upstash는 무료 한도 안이다.
9. 수익은 정비 연계 수수료와 프리미엄 구독 두 갈래를 검토한다.
10. 복제가 어려운 것은 차 안 실데이터, 시즌 이력, Pleos 탑재 위치다.

**시장은 이미 크고, 앞으로 Pleos 탑재 차량으로 좁혀진다.**

| 항목 | 값 | 출처·상태 |
|---|---|---|
| 국내 자동차 누적 등록 | 26,676천 대 (2026-06 말) | 국토교통부 보도자료 2026-07-30, https://www.molit.go.kr/USR/NEWS/m_71/dtl.jsp?lcmspage=1&id=95092268 |
| Pleos Connect 탑재 목표 | 2030년까지 약 2,000만 대 | 현대차그룹 뉴스룸, https://www.hyundaimotorgroup.com/en/news/hyundai-motor-group-redefines-in-vehicle-experience-with-pleos-connect-next-generation-infotainment-system |
| 2028년 누적 탑재(보도) | 약 700만 대 | 언론 보도 기준. 공식 원문 아님 |
| 목표 시장(TAM) | Pleos Connect 탑재 차량 | 위 탑재 목표에서 계산 |

**MAU 계산식: 탑재 차량 수 × 앱 설치율(a) × 월 활성률(b). a와 b는 (가정)이다.**

2028년 700만 대 기준(보도 값).

| a \ b | 30% (가정) | 40% (가정) |
|---|---|---|
| 1% (가정) | 21,000 | 28,000 |
| 2% (가정) | 42,000 | **56,000** |
| 5% (가정) | 105,000 | 140,000 |

2030년 2,000만 대 기준(공식 목표).

| a \ b | 30% (가정) | 40% (가정) |
|---|---|---|
| 1% (가정) | 60,000 | 80,000 |
| 2% (가정) | 120,000 | 160,000 |
| 5% (가정) | 300,000 | 400,000 |

- 계산식 예: 7,000,000 × 0.02 × 0.40 = 56,000.
- 설치율·활성률의 실측 근거는 아직 없다. 사용성 테스트 뒤 다시 본다.

**Retention은 장치 5개로 붙잡고, 목표는 (가정)이다.**

| 장치 | 동작 | 근거 |
|---|---|---|
| 감쇠 | 마지막 점검일 +14일부터 하루 −1 | 규칙 계산 |
| 7일 연속 | 연속 일수가 7의 배수인 날 +5 | 규칙 계산 |
| 해소 보너스 | 감점 항목이 사라지면 항목당 +5(하루 최대 +10) | 규칙 계산 |
| 월 시즌 | 매달 1일 관리 50에서 재시작, 지난 시즌 등급 기록 | 규칙 계산 |
| 대전 | 정차 중 5라운드, 등급 미반영 | 설계 |

- 목표 D7 ≥40%, D30 ≥20% (가정). 측정 전이다.

**비용은 공모전 기간에 약 $4로 계산된다.**

| 항목 | 계산 | 값 |
|---|---|---|
| `/chat` 1회 | 입력 2,500토큰 × $0.10/1M + 출력 300토큰 × $0.35/1M | ≈ $0.00036 |
| 하루 상한 500회 | 500 × $0.00036 | ≈ $0.18/일 |
| 22일(11/13~12/4) | 0.18 × 22 | ≈ $4 |
| Vercel Hobby | 무료(함수 월 100만, Active CPU 4시간) | $0. 단 비상업 조건 |
| Upstash 무료 | 월 50만 명령, 250MB | $0 |

- Hive 단가 출처: 공식 가격 페이지. 입력 $0.10, 출력 $0.35 / 100만 토큰(2026-11-09 확인).
- 한도를 넘으면 서버 기능만 멈춘다. 앱은 오프라인 음성과 연습 상대로 계속 동작한다.

**수익 모델은 2개를 검토한다. 전환율은 모두 (가정)이다.**
1. **정비 연계 수수료.** RED 경고·감점 항목에서 정비 예약·견적으로 연결하고 건당 수수료를 받는다. 수수료율 (가정).
2. **프리미엄 구독.** 시즌 리포트, 중고차 인수 시 차량 상태 리포트를 유료로 제공한다. 월 구독가 (가정).
- 두 모델 모두 실제 계약·단가 확인 전이다. 매출 추정은 넣지 않는다.

**확대는 3단계다.**
1. **시제품(2026):** 에뮬레이터 + 데모 프로필. 공모전 제출본.
2. **정식 출시(2027~2028):** Pleos Connect 탑재 차량 대상. 실차 권한 확인 후 경고등 기능 정식화.
3. **확장(2029~):** 차종·브랜드 확대, 중고차 상태 리포트 B2B, 보험·부품 제휴.

**복제하기 어려운 점은 3개다.**
1. **차 안 실데이터.** 리스너·capability·권한 협상을 차량 플랫폼 안에서 끝내야 한다. 서버만으로는 같은 값을 만들 수 없다.
2. **시즌마다 쌓이는 관리 이력.** 이력은 시간이 있어야 생긴다. 나중에 들어온 경쟁자는 같은 기간을 되살릴 수 없다.
3. **배포 위치.** Pleos Connect는 2030년 약 2,000만 대 탑재가 목표다. 앱이 그 인포테인먼트 계층 안에 있으면 설치 장벽이 낮다.
