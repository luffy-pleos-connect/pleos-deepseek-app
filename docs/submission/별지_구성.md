# 별지 PDF 구성 (D-06)

- 형식: A4 가로, 5~7쪽, DS 라이트 토큰 색 + Asta Sans
- 쪽 제목은 **결론 문장**으로 쓴다
- 작성자 정보 비움(DQ-06)
- 벡터 또는 2배 해상도, 본문 ≥10pt
- 최종 산출: `docs/submission/별지_MOCA.pdf`

## 쪽 구성 (초안)

### 1쪽 — "경고등은 켜짐만 알려 주고, 무엇을 먼저 할지는 알려 주지 않는다"
- J2 이야기 한 단락 (ABS 빨강 + TPMS 노랑이 함께 켜진 아침)
- 문제 3개: 급한 정도를 모름 / 상태가 흩어짐 / 이력이 안 남음
- 해결 한 줄: 부품 상태를 점수·등급으로 묶고, 할 일을 붙이고, 음성으로 답한다
- 그림: 문제→해결 대응표

### 2쪽 — "차 안에서 읽은 값이 등급이 되고, 등급이 오르는 것이 보인다"
- 구조도 (앱 / Vehicle SDK / Vercel / Hive / Upstash)
- 데이터 흐름: VHAL → Vehicle SDK → 앱 점수 계산 → 화면 / 요약만 서버
- 점수 공식 한 장: 카테고리 5 → 건강 → 종합(0.7·0.3) → 등급, RED 상한, 건강 문턱
- 실측 예: 실차 값으로 **B 73 (건강 84, 관리 50), A까지 7점**

### 3쪽 — "한 화면에 하나의 답만 남긴다"
- 홈·점검 결과·상태관리 스크린샷 3장 (실제 앱, 원본 해상도)
- 각 화면의 P1 표시
- 가로·세로 배치 차이 (P3 숨김 규칙)
- 화면 캡처 출처: `docs/evidence/G2/screens/`

### 4쪽 — "상태마다 다음 행동이 있다"
- 상태 5종(로딩·빈·오류·미지원·주행 중) 화면
- 데모 데이터 배지 / 오프라인 음성 배지
- 주행 중 제한 팝업
- 문구 표 (C-01~C-19 중 핵심 8개)

### 5쪽 — "차량 데이터 8종을 읽고, 제어는 하지 않는다"
- SDK/API 사용표: 도메인 / API / 권한 / 실측 상태
- capability 우선 처리
- `CONTROL_` 권한 0건
- 실연동 상태 정직 표기 (SOC 100 실값, 경고등 콜백, 색 정수 미확인)

### 6쪽 — "음성은 도구를 호출해 확인한 값만 말한다"
- 보이스 흐름도: STT → /chat → tool_calls → 앱 도구 실행 → tool 메시지 → 답 → TTS
- 도구 8개 표
- 필러 "확인해 볼게요", 4회 상한, 오프라인 의도 6개
- 시스템 프롬프트 핵심 3줄

### 7쪽 — "숫자는 측정한 것만 쓴다"
- 품질 표: 항목 / 합격선 / 측정값 / 증거
  - 점수 엔진 테스트 163/163
  - 서버 테스트 65/65
  - pleos_lint 0건
  - 앱 빌드·설치·실행 성공
- 미측정 항목 명시(성능·접근성·음성 50문항·6창)
- 사용 SDK·오픈소스 라이선스(Asta Sans OFL, Pleos DS 저작권 표기)
- 링크: GitHub·영상·숏폼

## 제작 방법

1. HTML+SVG로 만든다(`diagram-design` 스타일). A4 가로 297×210mm.
2. 폰트: DS의 Asta Sans(`pleos-ds/src/main/res/font/`). 임베드한다.
3. 색: DS 라이트 토큰 값만. 새 색 0.
4. PDF 변환: Chrome headless `--print-to-pdf` 또는 `wkhtmltopdf`. 폰트 임베드 확인.
5. 메타데이터에서 작성자·제목을 비운다(`pdfinfo`로 확인).
6. 쪽 번호·캡션을 넣는다.
