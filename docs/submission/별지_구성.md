# 별지 PDF 구성 (D-06)

- 형식: A4 가로, 5~7쪽, DS 라이트 토큰 색 + Asta Sans
- 쪽 제목은 **결론 문장**으로 쓴다
- 작성자 정보 비움(DQ-06)
- 벡터 또는 2배 해상도, 본문 ≥10pt
- 최종 산출: `docs/submission/별지_MOCA.pdf`

## 쪽 구성 (초안, 2026-11-14 기능 3개 구조에 맞춤)

> 모든 앱 화면 그림은 **새 화면을 데모 D3 로 다시 찍은 것**을 쓴다. 옛 화면(`docs/evidence/V9/`, `docs/evidence/G2/screens/`)은 쓰지 않는다. 새 캡처는 `docs/evidence/V12/`(2026-11-14)에 있고, 별지에는 앱 영역만 잘라 넣었다(`docs/submission/build/img/v12/`).

### 1쪽 — "경고등은 켜짐만 알려 주고, 무엇을 먼저 할지는 알려 주지 않는다"
- J2 이야기 한 단락 (ABS 빨강 + TPMS 노랑이 함께 켜진 아침)
- 문제 3개: 급한 정도를 모름 / 알아도 다음 행동이 끊김 / 관리 기록이 안 남음
- 해결 한 줄: 부품 상태를 구역 점수·등급으로 묶고(상태관리), 말로 묻고(보이스챗), 연습 상대와 겨루며 고칠 곳을 알려 준다(대전하기)
- 그림: 문제→해결 대응표

### 2쪽 — "차 안에서 읽은 값이 등급이 되고, 점수 기준의 출처를 구분해 말한다"
- 구조도 (앱 / Vehicle SDK / NaviHelper / 서버 `/chat` / Hive). 서버로 가는 것은 AI 질문 하나, 점검 기록은 기기 안 파일
- 데이터 흐름: VHAL → Vehicle SDK → 앱 점수 계산 → 기기 안 기록 → 화면. 서버는 AI 질문 때만
- 점수 공식 한 장: 구역 5 → 건강 → 종합(0.7·0.3) → 등급, 빨간 경고등 상한, 건강 문턱
- 출처 구분(최종정리 2.6절): 받는 항목·상태는 API, 경고등 색 **순서**는 ISO 2575, **감점 숫자는 설계 판단**
- 계산 예: 데모 D3 건강 85, 관리 53, 종합 75 · B (엔진 테스트가 같은 값으로 검산). 실차 값이 아니다

### 3쪽 — "앱을 켜면 점검이 끝나 있고, 상태관리가 해결 방법까지 이어 준다"
- 앱 시작 화면 · 메인 · 상태관리 스크린샷 3장 (데모 D3, 새 화면)
- 상태관리: 2D 자동차 그림(구역·바퀴 색), 구역 카드, 감점 원인별 해결방안 3종, [정비소 찾기], 용품 QR
- 2D 자동차 그림이 자리표시 그림이면 그 사실을 캡션에 적는다
- 가로·세로 배치 차이가 있으면 한 줄로 적는다(확인 필요)

### 4쪽 — "상태마다 다음 행동이 있다"
- 공통 상태 화면: 값을 읽는 중 / 등급 없음 / 측정 불가 / 주행 중(진입 제한, 축약)
- 상태관리 「해결할 항목 없음」, 보이스챗 「오프라인 음성」 배지
- 주행 중 제한 안내
- 문구 표 (C-01~C-19 중 핵심 8개)

### 5쪽 — "차량 데이터는 읽기만 하고, 제어는 하지 않는다"
- SDK/API 사용표: 도메인 / API / 권한 / 에뮬레이터 실측 상태
- `CONTROL_` 권한 0건
- 에뮬레이터 실측 한계: 엔진오일·브레이크액·변속기오일·워셔액·연료·타이어 현재 공기압 속성이 없어 읽히지 않음 → 실제 모드는 등급이 안 나오고 데모 모드로 확인. 배터리 SOC 100 실값 수신, 경고등 콜백 수신, 색 정수 미확인
- 내비 연동: 실제 모드(내비 검색 화면 열기)와 데모 모드(장소 목록 좌표로 안내) 차이

### 6쪽 — "보이스챗은 도구로 확인한 값만 말하고, 내비는 확인을 받은 뒤 조작한다"
- 보이스챗 흐름도: 음성·키보드 → /chat → tool_calls → 앱 도구 실행 → tool 메시지 → 답 → TTS
- 도구 10개 표(최신 점검·경고등·재점검·부품 상태·잔량·화면 열기·대전 화면·정비소 등 안내·경유지·안내 취소)
- 내비 확인 카드([안내 시작]/[취소]), 먼저 제안 우선순위(빨간 경고등 → 정비 항목 → 연료·배터리 10% 미만)
- 서버가 안 되면 기기 안의 답(의도 8개, 길 안내 포함). 주행 중 키보드 막음·2문장 이내
- 시스템 프롬프트 핵심 3줄

### 7쪽 — "숫자는 측정한 것만 쓴다"
- 품질 표: 항목 / 합격선 / 측정값 / 증거
  - 점수 엔진 테스트 247/247 (2026-11-14)
  - 앱 단위 테스트 196/196 (2026-11-14)
  - 서버 테스트 122/122 (2026-11-14)
  - pleos_lint 0건 (2026-11-14)
  - 앱 빌드·설치·실행: 새 구조로 다시 확인해 기입(확인 필요)
- 미확인 항목 명시: 실차(경고등 종류·색·권한), 주행 중 제한, 마이크 입력, 새 화면 처음부터 끝까지 녹화
- 사용 SDK·오픈소스 라이선스(Asta Sans OFL, Pleos DS 저작권 표기)
- 링크: GitHub·영상·숏폼

## 제작 방법

1. HTML+SVG로 만든다(`diagram-design` 스타일). A4 가로 297×210mm.
2. 폰트: DS의 Asta Sans(`pleos-ds/src/main/res/font/`). 임베드한다.
3. 색: DS 라이트 토큰 값만. 새 색 0.
4. PDF 변환: Chrome headless `--print-to-pdf` 또는 `wkhtmltopdf`. 폰트 임베드 확인.
5. 메타데이터에서 작성자·제목을 비운다(`pdfinfo`로 확인).
6. 쪽 번호·캡션을 넣는다.
