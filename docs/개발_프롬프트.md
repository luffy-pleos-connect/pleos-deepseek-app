## 2. 절대 규칙

1. **UI는 Android View(XML)다. Compose를 쓰지 마라.** `Theme.PleosConnect` + `pleos-ds` 모듈을 쓴다.
2. **색은 `@color/pleos_*` 만.** hex 금지. 글자는 `Pleos.Text.*`, 위젯은 `Widget.Pleos.*`.
3. **hex 색·임의 sp/dp·리플·무한 애니메이션·방향 고정·야간 강제·하드코딩 문자열 금지** (`pleos_lint` 규칙).
4. **차량 제어(`CONTROL_`) 권한 0개.** 읽기만.
5. **미지원·못 읽은 값을 "정상"으로 표시하지 마라.** 3상태(지원/미지원/일시실패)를 구분한다.
6. **데모 데이터를 실제 값처럼 표시하지 마라.** 데모 화면에는 `데모 데이터` 배지.
7. **키를 코드·APK·커밋·로그에 넣지 마라.** `HIVE_API_KEY` 는 `.env`(커밋 금지) 또는 환경변수만.
8. **TODO·FIXME·@Ignore·`!!` 금지.** 미완성이면 미완성이라고 보고한다.
9. **테스트를 먼저 쓰고 구현한다.** 특히 점수·판정 로직.
10. **판정은 실제로 돌린 명령의 출력으로만 한다.** "될 것이다"는 보고가 아니다.

## 3. 환경 함정 — 반드시 알아야 할 것

이 항목들은 실제로 시간을 잃은 지점이다. 같은 실수를 반복하지 마라.

### 3-1. 에뮬레이터는 headless로만 뜬다

```bash
# 창 있는 모드는 부팅 후 QEMU 메인 루프가 멈춘다 (13~18초 후 hang)
SDK="$HOME/Library/Android/sdk"
pkill -9 -f qemu-system-aarch64; sleep 3
rm -f ~/.android/avd/Pleos_Connect_v2.1.0.avd/*.lock
nohup "$SDK/emulator/emulator" -avd Pleos_Connect_v2.1.0 \
  -no-snapshot-load -gpu swiftshader_indirect -no-audio -no-window \
  > /tmp/emu.log 2>&1 &
sleep 55
"$SDK/platform-tools/adb" shell getprop sys.boot_completed   # 1 이면 성공
```
- **`-gpu host` 는 hang.** `swiftshader_indirect` 필수.
- `wm size` 로 창 크기를 바꾸면 윈도 서비스가 죽는다. 세로 창 시험 후 에뮬레이터 재시작이 필요하다.
- 메모리 24GB 맥에서 에뮬레이터 + Gradle 동시 실행은 위험하다. 하나씩 돌려라.
- release APK 첫 프레임이 **47초** 걸린다(swiftshader). `am start -W` 의 `WaitTime` 이 10초여도 정상이다. 크래시로 오판하지 마라.

### 3-2. `adb shell input tap` 이 앱 창에 닿지 않는다

앱 창이 화면 전체가 아니다. 실제 프레임:
```
frame=[853,90][2535,1300]
```
`uiautomator dump` 의 `bounds` 는 **이미 화면 절대좌표**다. 그 값을 그대로 쓰면 된다. 손으로 계산하면 어긋난다.

```bash
ADB="$HOME/Library/Android/sdk/platform-tools/adb"
"$ADB" shell uiautomator dump /sdcard/u.xml
"$ADB" shell cat /sdcard/u.xml | grep -oE 'text="[^"]*"[^>]*bounds="\[[0-9,]+\]\[[0-9,]+\]"'
```
**좌표를 스크린샷에서 눈으로 읽지 마라.** `bounds` 를 파싱해 써라.

일부 화면에서는 `input tap` 자체가 전달되지 않는다. 그럴 때는:
```bash
ADB shell am start -n ai.moca.app/.MainActivity --ez moca_autodemo true
```
디버그 빌드에만 있는 자동 시연 플래그가 홈→점검→상태→대전→보이스→AI질문까지 스스로 넘긴다. `MainActivity.viewLifecycleScopeAutoDemo()` 참고.

### 3-3. 네트워크

- **`INTERNET` 권한이 없으면 `SocketException: EPERM`.** manifest에 이미 있으니 지우지 마라.
- Android 9+ 는 평문 HTTP를 막는다. 디버그는 `app/src/debug/res/xml/network_security_config.xml` 에서 `127.0.0.1`·`10.0.2.2` 허용. **release 에는 넣지 않는다.**
- 에뮬레이터에서 `10.0.2.2` 가 막혀 있다. `adb reverse tcp:8787 tcp:8787` + `127.0.0.1:8787` 을 쓴다. debug `BuildConfig.SERVER_BASE_URL` 이 그렇게 돼 있다.
- release 는 `https://moca.vercel.app` 을 가리키며 **아직 배포되지 않았다**(404). release 로 보이스를 시험하면 항상 오프라인으로 떨어진다. 정상 동작이다.

### 3-6. DS(디자인 시스템) 사용 함정

- 카드는 **`style="@style/Widget.Pleos.Card"`** 로 적용한다. `android:background="@style/..."` 는 `InflateException` 이 난다.

- Fragment 전환은 `replace` 를 쓴다. `hide/show` 는 겹침 버그가 난다.

- AGP 9.5.1 + Gradle 9.9.0. Kotlin 플러그인을 따로 넣지 않는다(내장).

## 5. 네가 할 일 — 우선순위 순

### P1. `getLowTirePressure` 오해 수정 (기준 위반)

**문제**: 문서상 이 API는 **저압 임계값(kPa)** 을 준다. 저압 여부 플래그가 아니다.
**현재 코드**: `PleosVehicleSource.kt:173`(`readTireLowPressure`)이 `value > 0f` 를 저압으로 센다.
**고칠 방향**:
1. `getLowTirePressure` 반환값을 **임계값**으로 저장한다.
2. `getTirePressure(WheelArea)` 로 실제 압력을 읽어 임계값과 비교한다.
3. `getTirePressure` 가 실패하면 타이어 항목을 **측정 불가**로 표시한다(정상 아님).
4. 위 3가지가 안 되면 최소한 `value > 0f` 를 저압 개수로 세지 마라. 두 해석을 모두 방어하는 코드를 쓰고 주석에 근거를 남긴다.

### P2. 점검 기록 저장 (Room) — 평가 항목 I-06, S-05

**문제**: `RoomDatabase`/`@Entity`/`@Dao` 가 **0건**이다. 점검이 저장되지 않아 "마지막 점검"이 항상 미점검으로 나오고, 추이 그래프에 시간축이 없다.

**요구 스키마** (계획 11장):
```kotlin
@Entity(tableName = "inspections")
data class InspectionEntity(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val profile: String,          // "real" | "demo"
    val inspectedAt: Long,        // epoch millis
    val scenarioId: String?,      // 데모일 때만
    val itemsJson: String,        // 원본값
    val power: Int?, val brake: Int?, val tire: Int?, val electric: Int?, val safety: Int?,
    val health: Double?, val redCap: Boolean,
)
```
- `profile` 로 실제/데모를 **분리**한다.
- 대전 전적은 지금 `Prefs` 에 있으니 그대로 둬도 된다.
- 저장 후 홈의 "마지막 점검"이 `N일 전` 으로 나와야 한다.
- 상태관리 하단 추이는 **시간순 종합 점수**의 변화여야 한다. 현재는 "현재 카테고리 5개 막대"라 추이가 아니다.
- 데모 프로필은 시나리오별로 고정 기록을 쓰므로 Room 저장이 필요 없다. 실제 프로필만 저장해도 I-06은 통과다.

### P3. 첫 실행 화면 데모 배지 (C-01)

`fragment_onboarding.xml` 에 `데모 데이터` 문자열이 0건이다. 데모 모드가 켜진 상태에서 첫 실행 화면을 열면 배지가 보이게 하거나, 평가기준에 "첫 실행은 데모 이전 화면이라 예외"로 명시하고 문서를 고친다. **둘 중 하나만** 하면 된다.

### P4. 경고등 색 매핑 확정 또는 방어

`ScoreBridge.kt:136-137` 의 `Int.toEngineColor()` 가 `4=RED, 3=YELLOW` **가정**이다. 실제 값은 미확인(DDS 브리지 비활성).
- Virtual Console `/vehicle/state` 의 `telltales.bridge_ready` 가 `false` 면 주입 불가.
- 시도: `curl -X POST "http://127.0.0.1:8088/vehicle/telltales/simulator?type=ABS&state=On&color=Red"`
- 안 되면: 매핑이 틀려도 화면이 죽지 않게 하고, 기대값을 "미확인"으로 문서에 남긴다.

### P5. 세로 창

`wm size 840x1184` 로 바꾸면 앱 창이 뜨지 않는다. `layout-port/` 는 이미 있다.
- 시도: `wm size` 대신 `wm density` 만 바꾸거나, 에뮬레이터 재시작 후 재시도.
- 안 되면 평가기준 §7 "판정 불가"에 근거와 함께 남긴다.

### P6. 대전 데모 모순 해소 (권장)

`docs/evidence/G2/demo-battle-discrepancy.md` 참조.
현재 D3 대전은 **승패만 계획 표로 덮어쓴다**(`Demo.applyFixedRounds`). 그래서 5라운드가 `50:90` 인데 승으로 표시되는 모순이 있다.
**권장 해결**: 라이벌 카테고리를 조정해 **실제 계산으로 2:1** 이 나오게 한다. 그러면 고정 덮어쓰기를 제거할 수 있다.
예: 라이벌 타이어 100→70 이면 내 타이어 75가 승 → 3:2. 원하는 라운드 진행이 나올 때까지 `Seeds.kt` 의 라이벌 값을 조정하고 `DemoHistoryTest` 로 고정한다.

### P7. (선택) Vercel 배포

`api/index.mjs` + `vercel.json` 은 준비돼 있다. 사람이 `vercel login` 해야 하므로 **네가 하지 마라**. 배포 후에만 release `SERVER_BASE_URL` 을 실제 주소로 바꾼다.
