# Hive 실호출 검증 (2026-11-10 02:10)

- 목적: `/chat` + 도구 호출 왕복이 실제 Hive에서 동작하는지 확인 (VQ-02·VQ-03 핵심)
- 키: 서버 환경변수로만 주입. 화면·로그·문서에 출력하지 않았다.
- 명령: `server/local.mjs` (포트 8799) + curl 2회

## 도중에 발견한 결함 2건 (고침)

1. **Hive(DeepSeek)는 tool_calls가 오면 `content`가 빈 문자열이다.** 서버가 `content`만 보고 502를 돌려주고 있었다.
   → `message.tool_calls`를 보존하고 `content`·`reasoning_content`를 함께 반환하도록 고쳤다.
2. **추론형 응답은 `reasoning_content`에 답을 넣고 `content`를 비운다.** `max_tokens 60` 시험에서 확인.
   → 서버는 둘 다 반환하고, 앱(`VoiceAgent`)은 `content`가 비면 `reasoning_content`를 쓴다.

- 테스트: 서버 65→**68**, 앱 28→**29** (각각 tool_calls 보존·reasoning 폴백·전부 빈 경우 502 케이스 추가)

## 지연 평가 (VQ-07 참고)

| 구간 | 목표(p50) | 측정 |
|---|---|---|
| 필러 TTS | ≤2초 | 앱이 tool_calls 수신 즉시 재생. 1턴 지연 3.54초 안에 포함되므로 **미달 가능성** |
| 답 음성 시작 | ≤6초 | 1턴 3.54 + 2턴 4.12 = **7.66초** → **미달** |

- 두 턴 합계가 7.66초로 목표(6초)를 넘는다. 개선안: ① 모델을 더 빠른 것으로 ② system 프롬프트 축소 ③ 자주 묻는 질문은 도구 1회로 끝내기.
- 정직하게 "미달"로 기록한다.

## 결론

- `/chat` + 도구 호출 + 안전 첫 문장 + 숫자 인용이 **실제 Hive에서 확인됐다.**
- 지연은 목표 미달이다. 2차 PT 전 개선 대상.
